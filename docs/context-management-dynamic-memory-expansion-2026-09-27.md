## 开发范围与语义

本轮承接[人物后果记忆首版](context-management-dynamic-memory-runtime-2026-09-27.md)，没有扩大上下文预算，也没有增加模型调用。仍只从经过现有后果提交器和本地守卫的分支结果建立凭据，不从普通摘要或自由文本直接确认事实。

| 类型 | 本轮确认范围 | 不推断的内容 |
| --- | --- | --- |
| 人物 | 延续死亡、离队、失踪、受伤、确认存活 | 未经审核的新人物后果 |
| 物品 | 明确改变的持有人、位置、永久毁坏 | 任意自定义属性；位置清空后的去向；未改变字段的新依据 |
| 目标 | 进行中、完成、转化、放下；转化后的后续目标独立记录 | 目标标题本身已经发生；目标完成的具体过程 |
| 剧情线 | 问题待处理、已解决、已放下 | 问题标题是真实结论；未提供的问题答案 |

例如 `剧情问题「陆照临是否已经出发」：已解决。` 只表示账本状态，不授权正文回答“陆照临已经出发”。人物或物品名称来自相同原因分支中的实体登记，事实正文不用模型重新总结。

## 有效性与选择

1. `committed-outcome-memory/2` 继续绑定原因分支、父分支、故事包、正文、行动输入及审核内容；各条记忆另绑定已提交状态。目标和剧情线核对实际账本 ID、状态、标题、逐字依据及本次声明的依赖或元数据；转化目标同时核对后续目标的 `previousGoalId`。
2. 人物、目标、剧情线使用当前账本的 `causeBranchId` 和状态哈希。物品状态没有这个专用字段，因此比较完整祖先链的相关物品快照，只有最新实际变化所在分支的凭据可用。
3. 物品转交或落地造成的隐式持有/位置清空也参与失效判定。即使经历 A → B → A，也不能复活第一次 A 的凭据；中间分支没有记忆凭据时，状态变化仍使旧记录失效。
4. 清空位置或持有字段不生成猜测去向；也不会借用另一个继承字段生成新确认事实。永久毁坏会淘汰此前位置和持有记忆。
5. 按当前模块中的人物、物品、地点以及本次行动明确提及的实体筛选。目标/剧情线通过明确依赖、标题中的相关实体或行动提及的完整标题匹配。不把所有进行中目标、全部未解决问题自动塞入提示。
6. 四类事实共用最多 4 条、800 字符预算，按祖先由近到远选择，整条取舍。离开相关上下文就不装载，重新涉及时再读取。这里的字数是事实内容上限，总预算仍由原有预算器决定。
7. `chapter` 和 `repair` 只通过动态记忆携带一次短事实；同源证明保留在完整 bundle 与事实/grounding 阶段。没有追加完整历史正文、全部记忆或另一份摘要。

本版不提供语义相似检索或模型自动压缩；标题/依赖没有匹配时会保守漏选。当前状态和其他已授权证据仍由原有上下文投影提供，不能用扩大记忆注入补偿未知的语义覆盖率。

## 兼容与事务

- 已存的 v1 人物记忆按照 v1 原契约验证，只读兼容；不批量重写旧分支，也不把旧物品/目标/剧情线历史自动升级为确认记忆。
- 新提交必须使用 v2。API 拒绝凭据降级，预生成规则升为 `prepared-player-turn/21`，防止旧待提交草稿跨版本使用。
- 凭据与正文、状态仍在同一分支 JSON 和事务内提交；无新增数据库表或迁移，后代仅建立本回合继承视图，不重复持久化旧记忆。
- 失效仍是读取时省略，并保留原始原因记录；尚未实现通用 `candidate/unknown/rejected` 持久化工作流。
