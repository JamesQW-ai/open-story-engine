本轮完成路线局部大纲的基础：将当前目标、开放问题、人物依赖冲突及完成条件绑定到正式分支。大纲由代码整理已确认账本，不把未来剧情建议变成已发生事实；NQ-001 继续暂缓。

## 已实现

新开局和正式续写在保存分支时附带 `routeOutline`，契约版本为 `route-outline/1`。读取接口为 `GET /api/v1/sessions/{session_id}/route-outline?branch_id={branch_id}`，可在默认只读模式使用。

| 内容 | 行为 |
| --- | --- |
| 分支绑定 | 绑定故事包版本、模块摘要、契约、当前分支及祖先状态／正文／后果记录；兄弟分支不能共用依据 |
| 目标和开放问题 | 保留各条目的状态、来源、目标 ID 和完成条件；旧目标被放弃或转化后，不再排入待推进步骤 |
| 完成条件 | 目标要求 `completed`，问题要求 `resolved` 或有依据的 `abandoned`；须有当前祖先链中的对应变更和正文引文才确认已满足 |
| 人物依赖冲突 | 已确认死亡、离队、失踪的人物仍被活跃目标依赖时，改列 `review_dependency`，不安排该目标直接推进 |
| 待处理步骤 | `pursue_goal`、`address_thread`、`verify_status`、`review_dependency`；这些是工作类别，不授权玩家尚未选择的行动 |
| 旧存档恢复 | 无大纲时只读重建；无目标／问题账本时保留 `unknown`，先核实状态；经过验证的新开局使用官方入口明确声明的初始目标 |
| 过期／被改写的大纲 | 每次读取重新核对原始记录；失效保存副本不能抹除待办或伪造完成，返回 `storage=reconstructed`，不静默改写存档 |
| 结束路线 | 返回 `actionable=false`，保留未完成条目，不把提前结束伪装成所有问题已解决 |
| 卷与 Arc | 尚无明确路线归属资料时返回 `null`，含义为未知，不用回合数推测卷／Arc |

来源分为官方开局声明 `opening` 和当前路线正文 `narrative`。正文来源同时检查 `causeBranchId`、引文和对应 `consequenceUpdate`，并验证目标依赖一致。新目标、目标转化的后继目标、新增问题使用原提交规则生成的 ID 核对，不通过相似标题猜测关系。

普通玩家页面没有新增技术字段或调试按钮。大纲已经保存并可读取，但本轮尚未把它接入自动剧情规划提示。

## 写入和恢复保障

- 大纲不修改 `branchState`；人物生死、道具和目标仍受原业务守卫约束。
- 续写大纲与正文在同一正式提交事务中写入；大纲失败时不留下正式子分支，重试复用已有 ready 正文，不重新生成。
- 开局先完成大纲构建再创建会话，构建失败不会留下半成品存档。
- 幂等重试返回同一已保存大纲。重启通过正式存档恢复，无需额外模型调用或新数据库表。
- 只读接口不创建、迁移或修改数据库；失效包绑定、损坏账本返回受控错误。
