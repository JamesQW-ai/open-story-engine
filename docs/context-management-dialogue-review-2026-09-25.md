## 实现与边界

- `reader_scene_review.py` 增加 `scene_speaker_candidates`：保留玩家及正文叙述中明确出现姓名的已登记人物；对开场关系中明确命名、在当前叙述出现且当前公开证据可核实的角色称呼，生成 `scene-speaker:` 标识。已登记角色不重复生成临时标识。该表只供审核，不登记角色或写入权威状态。
- 当前失败稿的候选表由 7 名主要人物收敛为玩家与守门弟子两项。它是候选集，不证明在场、说话或知情。纯代词链、同名角色、引述嵌套仍需进一步验证；人物名与 ID 一致也不等于完整的语义归属证明。
- `api_narrative.py` 将同一候选表用于模型输入及当前稿校验，包括缓存复用。新运行路径要求 `speakerName` 与候选 ID 对应，缺失或冲突进入审核格式错误，不以改写正文来伪装修好。
- `scene_grounding.md` 的对白契约改为先列 `premises`，再判断发言用途；每项前提要绑定当前台词逐字片段及当前输入中的公开来源。`current` 不属于事实前提的合法分类；不能以它免除设施、规则等断言的依据。
- `premises` 现在同时要求逐字 `quote` 和标准化 `claim`；前者绑定当前台词，后者用于核对设施、规则和因果前提。玩家无来源的当前观察重复、或任意角色无来源的纯未知重复，不授予事实权限；NPC 的 `current` 前提仍是格式错误，不能借此绕过设施、规则等断言的依据。
- 即使整段仍标 `current`，NPC 已列出的缺证事实前提也会独立拒绝；NPC 有事实前提时必须提供获取途径。获取途径只证明信息如何传给角色，不能替代事实来源。
- 使用既有 grounding 调用，没有新增审核模型轮次、完整历史或全量人物背景。此次没有修改正文写作提示，原始失败正文和来源记录保持原样。
