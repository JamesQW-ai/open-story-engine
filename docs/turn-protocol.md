# 单回合协议

## 目的

本协议定义一次玩家输入如何成为可审计的游戏回合。它约束实现，不要求玩家在 CLI 中理解内部结构。

```text
玩家输入
  -> 行动解析
  -> 规则检定
  -> 原子持久化
  -> 叙事生成
  -> 面向玩家的回合结果
```

## 输入与输出边界

`TurnRequest` 至少包含：

- `sessionId`：目标会话的稳定 ID。
- `input`：玩家自由文本，保留原文。
- `requestId`：调用方生成的幂等键；重复提交不得创建两次事件。

一次成功的 `TurnResult` 至少包含：

- 已确认的 `ActionIntent` 与 `Resolution`。
- 新的状态版本、当前节点与可读的状态差异摘要。
- 本回合事件 ID。
- 叙事文本或明确的 `narrationPending` 状态。

内部 `ActionIntent` 只表示当前尝试，不表示一定成功：

```text
actionType: investigate | negotiate | risk
targetId: StoryPackage 内已存在的实体 ID 或 null
approach: 受长度限制的行为摘要
```

行动解析器只能从受限枚举和当前故事包实体中取值。解析器无法确定时，返回可恢复的澄清结果，不生成 `ActionIntent`，也不创建游戏事件。

## 执行顺序

1. 根据 `sessionId` 读取会话、当前状态、故事包版本和已处理的 `requestId`。
2. 若 `requestId` 已存在，返回原结果，不重新检定或重新写入。
3. 对输入执行长度、空白与字符规则检查。
4. `ActionParser` 生成并校验 `ActionIntent`；失败则保留原状态并返回澄清。
5. `RuleEngine` 使用当前状态、故事包规则和可注入随机源计算 `Resolution` 与 `StateDelta`。
6. 在一个 SQLite 事务中：校验 `StateDelta`、追加 `game_events` 记录、更新状态快照、写入 `requestId` 与新状态版本。
7. 在事务提交后，`ContextBuilder` 从已确认的新状态构造受预算限制的叙事上下文。
8. `Narrator` 生成剧情文本，并将文本或失败状态关联到本回合事件。
9. 向 CLI 呈现正文、可读状态变化和下一步输入提示。

## `Resolution` 约束

`Resolution` 由代码生成，至少包含：

- `outcome`：`success`、`partial_success`、`failure`、`blocked` 或 `terminal`。
- 使用的属性、难度、随机结果和修正值（若进行了检定）。
- 明确的 `StateDelta`：新增/移除物品、关系变化、旗标变化、已知事实、节点或地点变化。
- 面向叙事器的已确认事实列表，而非开放式剧情指令。

`blocked` 表示行动不满足前置条件。它可以产生角色反应或环境压力，但只有规则中明确定义的代价才允许进入 `StateDelta`。

## 持久化规则

每个已提交回合应至少保存以下逻辑数据：

| 记录 | 责任 | 关键内容 |
| --- | --- | --- |
| `game_sessions` | 会话仓储 | 故事包版本、当前状态、状态版本、终局标记。 |
| `game_events` | 回合服务 | 原始输入、行动、检定、状态差异、旧/新版本、叙事状态。 |
| `llm_audits` | LLM 适配层 | 模型标识、提示词版本、请求摘要、原始输出、解析或调用错误。 |

叙事生成不属于状态事务。事务成功后叙事器失败时，事件保持有效并标记 `narration_pending` 或 `narration_failed`；系统可在不重新检定的情况下重试叙事。

## 失败处理

| 失败类型 | 状态处理 | 玩家反馈 |
| --- | --- | --- |
| 输入为空或超限 | 不变 | 要求用一句明确行动重试。 |
| 行动解析失败 | 不变 | 用故事内语境或简短问题请求澄清。 |
| 目标不存在或不可达 | 不变，除非规则明定代价 | 说明当前障碍并保留自由输入。 |
| 规则检定失败 | 写入定义好的失败 `StateDelta` | 以叙事方式呈现代价、风险或新压力。 |
| 数据库事务失败 | 不变 | 提示本回合未保存，可以安全重试。 |
| 叙事器失败 | 规则结果已保存 | 显示已确认的状态摘要，并允许重新生成叙事。 |

绝不通过让 LLM 猜测状态或重放随机检定来修复失败回合。

## 上下文最小集

`ContextBuilder` 只向 LLM 提供完成当前职责所需的数据：

- 世界不可违背事实和叙事约束。
- 当前节点、地点、近目标与压力。
- 当前状态中与本回合相关的物品、关系、旗标和已知事实。
- 节点的 `contextRefs` 和有限数量的近期事件摘要。
- 对叙事器而言，`Resolution` 中已确认的事实与允许描述范围。

不得注入完整事件史、整个故事包、数据库原始行、密钥或其他会话数据。

## 终局

`RuleEngine` 在回合完成后检查结局条件。命中结局时，在同一事务内把会话标记为终局并创建终局事件。终局会话拒绝新的普通 `TurnRequest`，但允许读取状态、回顾事件和重新生成已保存的叙事。
