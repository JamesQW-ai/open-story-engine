## 结论

通用自定义行动机制已实现并通过本轮专项验证：核心与 API 共 320 项测试通过（27 项专项包含在其中）；真实模型完成原问题复验、物品改造后的连续五回合，以及重启恢复和兄弟分支隔离。可以继续 C 的人物图谱联动。该结论不等于所有自然语言输入均能一次成功，也不代替 P3/P4 的完整长篇路线与终局验收。

## 范围与原则

本轮继续批次 B，完善任意自定义输入的通用处理机制。交易、拒绝、提问、移动、物品改造、人物后果等只是验证样本，不是后端的场景白名单。不修改冻结小说、已发布故事包或桌面布局。

“必须响应”指保留玩家完整原意，并在正文与状态中落实本回合明确要求的行动及结果；不等于忽略已发生事实、世界铁律或输入中的条件。原著未来、阵营利益与主线需要不能作为吞掉玩家选择的理由。真正冲突或存在关键歧义时，返回具体说明或澄清；不得冒充成功。

## 本轮实现

1. **通用行动契约与独立授权审核。** `reader_actions.py` 记录 `steps`、`introductions` 和 `stateChanges`。步骤追溯到完整输入，区分玩家授权与有前因的 NPC / 环境反应。分句只是覆盖索引，否定、引述、条件、先后顺序始终结合原句解释。NPC 命令不自动授权玩家执行。写正文之前另用一次聚焦授权的审查，只查看玩家原话、上一段实际正文、父状态及候选步骤/变化，逐项检查依据；不能因规划器已登记就视为获准。
2. **可扩展的持续状态。** 动态属性记录在 `readerEntityStates`，无需为每种玩法新增分支判断。物品持有人、人物与物品地点仍使用既有权威字段；死亡/离队、目标仍经过专门的不可逆后果与目标历史规则。新实体复用已有分支扩展校验并登记来源步骤。未发生变化的记录会被消除，未知旧值不能凭正文猜测。
3. **独立提取正文事实。** 提取器只看前文、已有状态、实体目录、属性名词表与本段正文，不接收用户输入、预期结果或最终状态。逐段区分实事、话语、意图、假设、回忆和背景；承接语中的持续状态也需提取，由代码过滤已登记的相同状态，再由语义审查对照原始输入及契约。
4. **事实与契约双向闭合。** 每项请求必须有正文回应，每项契约变化须有证据，每个提取事件都须得到核对。未登记的重要实体、持续变化、错误持有人、额外决定均不能提交。按正文顺序处理状态，允许开头提及旧持有人，但不允许转交后又偷偷回到旧持有人。中文动态属性值的等义判断依赖语义审查；实体引用、结构化值、证据覆盖、永久状态和落盘由代码核对。
5. **保留有效正文并限制重试。** 事实证据只要求段落编号，原文由代码取出；段落编号或提取格式错误先修复记录；后果证据映射错误先修复审查记录。正文出现规划未预见、但合理发生的持续后果时，可提出 `additionalChanges`，通过同一授权、引用、证据与父状态检查后补记；不能借此认可越权行为或偷偷改写已规划结果。正文确有问题时才局部修复，达到现有上限仍失败则不提交正式分支。全文 SHA-256 绑定已审查正文，防止审查后追加未经检查的行动。
6. **沿用单层预生成。** 当前页面的预设方向仍只准备一回合；自定义输入提交后生成。新规则使用 `prepared-player-turn/11`，旧草稿不得绕过新契约。未选分支不修改正式状态，不触发实时生图。

## 完成边界

有限测试不能证明模型对所有自然语言都能一次理解正确。本轮交付的是统一处理与校验路径，后续新增输入类型应补充回归样本，不按人物名字或场景关键词扩展业务分支。

有效自定义样本的完整 HTTP 请求耗时约 26–102 秒，仍需优化；这不是首字延迟或 P95，也不能代表预设方向命中缓存的等待时间。没有汇总 token 账单，不据此推算费用。本轮未主动请求实时生图。

独立授权检查与事实提取各增加一次模型调用，必要的计划修正或后果补记还会增加调用，因此自定义回合延迟有所增加；预设方向仍在阅读期间预生成。真实调用需同时记录运输超时、修复次数和最终输出，不能只报成功样本。动态状态目前供生成、审查与存档使用，人物图谱的可视化仍属于 C；长篇伏笔回收与自然终局属于 D / P4。
