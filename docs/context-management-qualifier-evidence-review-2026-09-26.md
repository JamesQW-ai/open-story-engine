后续新场景结果见[议事殿留出复审](context-management-qualifier-heldout-review-2026-09-26.md)：8/9 严格匹配，暴露外层不确定性与内层位置命题的契约边界；下文保留原开发集记录。

## 本轮契约

本轮承接[限定类型配对复审](context-management-qualifier-review-2026-09-26.md)，实现可检查的限定线索与作用范围。范围仍是官方长篇 `taixu-relics-part1@0.1.3` 同一场景的位置命题，不是通用语义解析器或正式输出审核器。

[契约实现](../test_support/context_qualifier_evidence.py)保留既有命题状态及关系结构，增加主体、边界、位置主句锚点。每项限定需提出具体线索、作用范围；条件限定还需提出包含条件线索的完整前提。

| 字段 | 责任 |
| --- | --- |
| `unitIds` | 命题及必要限定所在原文单元，按原文顺序排列 |
| `anchors.subject/boundary` | 主体和边界称呼引用；无法定位时保留 `null` |
| `anchors.position` | 位置主句的引用列表，包括否定和不确定表述 |
| `limitations[].cue` | 触发该标签的具体原文线索 |
| `limitations[].scope` | 模型声明该限定作用的位置主句 |
| `limitations[].premise` | 条件前提的引用列表，非条件类型为空 |

模型仅选择 `{unitId, quote, occurrence}`。`occurrence` 从 0 开始区分同一单元内重复引文；程序从原文计算绝对 `start/end`，采用 Python Unicode 码点和半开区间，不要求模型数偏移。程序校验引用存在、单元归属、出现次数、跨度顺序及重叠。

契约检查与语义审核分开：

- 格式、伪造引用或不存在的出现序号返回 `invalid_response`。
- 引用合法但条件缺前提、声明作用范围不同于位置主句、可能性线索落在其他语句、仅用连接词或整条主句作可能性依据等，返回具体 `issues`。
- 实体表唯一明确称呼与 `unresolved_subject/unresolved_object` 同时出现时，报告冲突。候选关系的实体 ID 与称呼锚点不一致时也报告问题。
- 保留完整 `proposedResponse`；转换出的兼容评分视图不删除、改写任何标签，也不把 `needs_review` 升级为 `candidate`。
- 所有结果均为 `semanticStatus=unverified`、`reviewRequired=true`。`structurally_valid` 仅表示契约检查没有发现问题，不能视为语义支持或生产放行。

单独的“就／便”等不能证明认识可能性，是窄范围诊断规则；这不是自动否定所有含这些词的表述。隐含不确定性、否定、同词不同义仍需语义复核。测试明确保留“想必”“不可能”及名牌文字“可能”等例子，验证程序不会因跨度合法就给它们语义批准。后一个例子可能通过结构检查，这正是结构检查的能力边界。

## 验证设计

[契约测试](../tests_py/test_context_qualifier_evidence.py)采用显式人工构造的结构提案；它们只验证程序行为，不冒充模型提取结果。[实验测试](../tests_py/test_context_qualifier_evidence_eval.py)检查有限调用、盲输入、旧证据保护、保存失败停止及评分复算。

[实验脚本](../test_support/context_qualifier_evidence_eval.py)对上一轮冻结的 9 条样例各调用一次，总上限 9 次，无重试、修稿或金标修改。模型输入仍仅为完整稿、原文单元和无位置真值的实体称呼。[新提示](../test_support/prompts/context_qualifier_evidence.md)使用结构契约，不携带旧响应、期待标签、完整上下文包或来源真值。

评分包括两部分：兼容视图必须严格匹配原金标，同时本轮契约不得有 `issues`。这是开发集评分，不替代逐条检查线索是否确实支持标签。旧版结果仅作为历史诊断，不将不同时间、不同输出契约的单次成绩直接归因为稳定提升。

## 逐项复审与成本

| 样例 | 实际提取与复审 |
| --- | --- |
| 原失败“如果……就在……” | 只提取 `condition`；线索“如果”绑定完整放行前提，作用于位置主句 |
| “伤者就在封山线内” | 当前关系候选；主体、边界及位置主句均准确，无额外限定 |
| “伤者可能在封山线内” | 仅 `modality`，具体线索“可能”；没有再把“伤者”误标为未知主体 |
| “如果……也可能……” | 保留 `condition` 与 `modality`；前提与“可能”分别提供依据 |
| 原失败“只要……便在……” | 只提取 `condition`；“只要”绑定点头前提，不再以“便”证明可能性 |
| “伤者或许在封山线外” | 仅 `modality`，线索“或许”位于位置主句内 |
| “只要……或许……” | 两项限定正确共存；条件线索引用了“只要守门弟子点头”完整短语，含义及作用范围正确 |
| 无关前句“可能点头” | 只选择后句明确位置，没有借用前句线索 |
| 无关前句条件动作 | 只选择第三单元的位置句，没有借用前句条件 |

总计 3 个当前关系候选、6 个待复核项，9 次位置命题均匹配，无遗漏、额外提取、重复或格式错误。双重限定样例有一项主句引用未包含句末句号，但完整保留了主体、可能性与位置表达；契约按实际子串定位，不要求把标点作为语义依据。

9 次请求均为 `direct`，配置模型 `deepseek-v4-flash`，响应模型 `deepseek-flash`，结束原因均为 `stop`。输入 token 合计 6,744、输出合计 2,006，请求中位耗时 1,229 ms；提示为 1,305 字符。上一轮澄清提示的输出合计为 781 token，本轮结构化输出更长。不同时间的单次实验不支持延迟归因；后续需要关注这项成本，不能仅凭匹配率提高就宣称整体上下文工程已优化完成。
