# 玩家 CLI 的 SSE 响应缺少可用正文

## 状态

人工验收通过，持续观察。非流式的 `evaluate:live` 已有两次完整 `6/6` 通过证据；当前 `v0.8` 真实玩家 CLI 已完成一次宽泛目标到动态章节的端到端回归。端点的单次超时或无正文仍由重试与回退处理，尚不能据此宣称稳定性已完全证明。

## 2026-09-04 真实观察

在临时 SQLite 数据库中以 `STORY_PLANNER=openai npm run co-create` 运行固定的 `rainy-waiting-room@0.1.0`。先选择原著方向“追查十七号柜”，再输入“先让姜序带路去积水尽头确认唐栖的情况”。

- 三次 `direction_evaluator` 调用均成功，说明自由文本映射与该模型端点可用。
- 一次 `branch_planner` 在两次本地修复尝试后，最终正文为 382 字，被 400 至 600 字正文契约拒绝；没有追加分支。
- 后续一次 `branch_planner` 返回 SSE，但没有 `choices[0].delta.content` 或 `choices[0].message.content`，网关拒绝该无正文响应；没有追加分支。
- 控制台的原著段落会以 12 字、16ms 的本地节奏输出，但本次没有获得已验收的 LLM 动态剧情，因此不能据此宣称真实 SSE 动态分支展示通过。

本文档不复写端点正文、提示词或密钥；本次无正文失败也没有可供分析的模型正文。上述结论只说明该代理的本次 SSE 响应无法被当前 OpenAI 兼容契约接受，不能在未保留原始 SSE 事件的前提下断言是上游格式异常还是兼容性差异。

## v0.8 篇幅契约更新

本节开头记录的 382 字失败以及后续人工试玩中的 659 字失败，均发生在 `co-creation-planner-v0.7` 的固定 400 至 600 字文学长度契约下。`v0.8` 已移除该契约，改由自适应章节推进元数据约束“宽泛目标只展开当前阶段”，正文仅保留技术安全上限。因此这些长度失败是历史观察，不再是当前 Planner 的拒绝条件；新的真实人工验收仍需验证模型是否按阶段推进而非一次跳过长期目标。

## 脱敏 SSE 探针

同日的独立固定 JSON 探针返回 HTTP `200` 和 `text/event-stream`。事件顺序为 `delta.role`、多段 `delta.reasoning_content`、多段字符串 `delta.content`、无 choices 的 `usage`、`[DONE]`。现有解析器会跳过角色、推理和用量事件，并在 `delta.content` 到达后正常拼接 JSON；已由离线回归覆盖。

因此，前述无正文失败不是已知的事件字段兼容问题，而是该次剧情规划响应在流结束前未出现任何可用正文。仍需要一次成功的真实动态分支回归，才能关闭本问题。

同日以新临时会话重跑相同自由文本路径时，再次复现无正文错误。该错误原本会使 `co-create` 退出；现已改为显示错误后保留当前会话和输入提示，玩家可以重试或选择已公布方向。该修复不把失败响应当作成功分支。

## 成功会话证据

在新的临时 SQLite 会话中，使用相同的原著入口与自由文本“先让姜序带路去积水尽头确认唐栖的情况”重跑：

- `direction_evaluator` 一次调用完成：SSE、HTTP `200`、1,235ms。

- 新增第 2 个分支节点，`canonicalRelation=diverged`、`selectedDirectionId=direction_rescue_first`、正文长度 456 字。
- 终端到达独立的 `剧情：` 输出路径，并展示后续两个方向；`llm-audits` 可读取上述脱敏传输观测。

这证明玩家 CLI 的 SSE 解析、动态节点持久化与逐段展示链路可以完成，但不足以证明端点稳定可用。

## 影响范围

- `co-create` 会把失败显式显示给玩家，并且不会创建不完整分支。
- 网关会仅对 HTTP `200`、流式响应且结束时没有可用正文的情形，以相同请求进行一次非流式 JSON 回退；审计保留首次 SSE 失败及回退结果。超时、HTTP 错误、畸形 SSE 事件和模型正文不合格均不会触发回退。
- 真实玩家 SSE 动态生成可成功，但当前端点存在无正文的偶发失败；回退可提高单次人工试玩完成率，尚未在当前提示词版本下获得真实人工验收。
- 已关闭的非流式批量超时问题不受影响。
