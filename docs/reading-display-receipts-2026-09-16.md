## 交付结果

本轮为已保存的续写正文接入客户端展示回执，并按生成尝试汇总保留期内的 token 回执。区分生成完成、正式提交和展示确认；没有把提交成功当成读者已看到正文。

前端仅在正式续写分支加载完成、非流式状态、至少一个正文段落进入视口且文档处于 `visible` 时准备回执；经过两个动画帧，再次核对可见性和节点连接状态后发送。分支切换和卸载会撤销待发送回执，网络失败最多重试一次，不阻塞阅读或显示额外按钮。刷新／回看可以重报，由后端去重。

这证明客户端报告了保存正文的可见段落，**不证明整段正文读完、用户理解了内容或画面未被其他窗口遮挡**。当前不统计开局、源章节回退、未确认草稿或图片的展示。

## 接口和绑定

接口仅在受控游玩模式开放：

- `POST /api/v1/sessions/{session_id}/reading-receipts`，正文为 `{"branch_id":"..."}`。客户端不传 token、草稿键或展示时间。
- `GET /api/v1/sessions/{session_id}/turn-usage`，返回当前保留的续写生成尝试汇总。

服务端从正式分支读取 `preparedTurnKey`，再核对草稿的存档、父分支及本次正式提交的 `committed_branch_id`。跨存档或不存在的分支返回 404；额外客户端用量字段被请求模型拒绝。已有正文但统计绑定缺失／被淘汰时，返回 `recorded: false`、`reason: measurement_unavailable`，不创建替代任务。

首次有效回执保存服务器接收时间 `first_display_receipt_at`；重复回执返回 `deduplicated: true`，不增加调用或 token。不会修改正式故事数据库中的正文、状态或用户授权。

统计读取使用现有内存任务，或只读 SQLite 连接（`mode=ro`、`query_only=ON`）加载仍在保留期内的私有记录；不会调用数据库初始化／迁移，也不创建缺失数据库。

## 统计口径

汇总 `scope` 为 `retained_turn_draft_attempts`，分为：

| 分组 | 含义 |
| --- | --- |
| `display_confirmed` | 有本次提交分支绑定及展示回执的生成尝试 |
| `display_unconfirmed` | 没有展示确认的尝试；包括未选方向、仍在生成、失败尝试、旧记录和回执未送达等，不能直接称为“实际未展示” |

两组都提供 `attempts`、`calls`、`reported_tokens`、`unreported_calls`、`unmeasured_attempts`、`tokens`、`queue_ms` 和 `complete_ms`，沿用 [耗时与用量口径](turn-usage-reliability-2026-09-16.md)。缺少回执时，`reported_tokens` 只是已知下界，`tokens` 保持 `null`。

累计按每次尝试分组：重试成功的正文被展示，只确认成功的那次；之前失败尝试的消耗仍在展示未确认组，不随最终成功结果一起转移。空分组为零，旧记录缺失用量不是零。

目前仍受私有草稿 600 秒有效期参数、128 项容量上限及存档删除规则约束。清理后的任务、旧版本缺少提交分支绑定的任务不能补造统计，**没有独立永久费用账本，也没有据此推出全历史展示率**。图片展示与生图成本不在本轮范围内。
