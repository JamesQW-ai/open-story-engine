## 范围与结果

完成 C 的第 1 步：统一人物展示数据。`journey` 接口为当前路线的人物提供可知姓名、姓名来源、头像引用、稳定的预设头像编号、人物状态及状态依据。人物详情沿用原入口，前端仅补充类型定义；头像绘制、灰度和状态标签样式属于后续第 2、3 步。

## 数据协议

接口为 `GET /api/v1/sessions/{sid}/journey?branch_id={bid}`。顶层增加 `branch_id`，用于明确这份展示数据所属分支。`people` 保留原有 `id`、`name`、页码、身份和简介等字段，增加：

| 字段 | 含义 |
| --- | --- |
| `name_evidence` | 已展示的姓名来源，包含 `branch_id`、`page`、`quote`、`source`；无可定位证据则为 null |
| `portrait.url` | 已发布、同源 `/images/` 下的头像引用；没有合法引用则为 null |
| `portrait.source` | `published` 或 `preset` |
| `portrait.fallback_key` | `person-1` 至 `person-8` 的稳定预设编号，由故事 ID 与角色 ID 决定；第 2 步再提供对应头像显示 |
| `status.code` | `unknown`、`alive`、`dead`、`departed`；`missing` 作为后续结构化数据的保留值 |
| `status.label` | 对应中文状态 |
| `status.permanence` | `temporary`、`permanent` 或 null |
| `status.evidence` | 本路线中已保存并向玩家展示的后果证据；无可靠依据则为 null |

`source` 使用 `narrative`（姓名依据）或 `consequence`（正式后果）。状态来源必须在所选分支的祖先链中，引用须存在于该页正文，且和该页保存的 `consequenceUpdate.outcomes` 对象、状态、永久性及证据一致。内部状态、其他分支和未来节点不能直接成为展示依据。

没有已确认后果时返回 `unknown`，不把“出场”自动等同于存活，也不把“不在场”推断为死亡、离队或失踪。当前运行时尚无专用失踪事件，因此本轮不会从原著简介或动态属性里的自然语言推导 `missing`。缺少可验证记录的旧存档同样保守返回未知。

## 已知人物与资料边界

- 原有保守出场识别继续使用。增加已审核且正文中已展示姓名的开局关系来源，修复顾长离开局已与陆照临互通姓名、却未显示陆照临的问题。
- 已有公开且可核对的后果记录可以保留对应人物；没有公开姓名的源人物仍不会因为存在于全书目录而出现。未建立可靠实体绑定的匿名人物暂不映射到隐藏真名。
- NPC 不再复用其他可玩角色的菜单简介，避免把其他角色知道的经历透露给当前身份。头部使用中性说明，详情仍从已读正文按原流程整理。玩家自身保留已选择的身份介绍。
- 不返回完整人物卡、私有身世、未来关系或生图提示词；头像只复用已发布的引用，未提供引用时返回预设编号。本步不生成或新增图片。
