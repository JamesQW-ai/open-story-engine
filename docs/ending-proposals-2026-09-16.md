本批实现 P6 终局证据提案与受控提交的后端契约。已有正文通过独立审查后仍保持可游玩，只有显式提交才结束路线；不新增正文生成或修复循环。NQ-001 与 SRC-001 继续暂缓。

## 提案、审查与提交

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/sessions/{id}/ending-proposals` | 提交 `branch_id`、`request_id`、`outcome_summary`、`ending_quote`，执行一次独立审查并保存结果 |
| `GET /api/v1/sessions/{id}/ending-proposals/{proposal_id}?branch_id=...` | 只读查看审查、失败原因及当前是否失效 |
| `POST /api/v1/sessions/{id}/ending-proposals/{proposal_id}/commit` | 仅接收 `branch_id`；重新校验后原子提交结束状态及回执 |

写接口仅在受控游玩模式下提供，客户端不能提交 `approved` 或替代模型审查结论。当前不提供前端提案操作入口。

提案必须属于尚未结束、没有后续分支的路线末尾，已登记正常／偏离／失败收束意图，并满足对应必要账本条件。引文必须逐字出现在当前已保存正文中。条件不符时在调用模型之前拒绝；未配置审查模型返回 `ending_reviewer_unavailable`，不以 Mock 结果替代。

独立审查输入包含当前正文、提案说明、引文、目标、开放问题、冲突与有依据的人物后果。审查覆盖结局类型、问题交代、新增未解冲突和实际收尾四项；每项通过都需当前正文原句及理由，结论矛盾、缺项或伪造引文均失败。主动放弃不能仅凭目标状态被认定为失败结局。程序只校验结构与引用，语义判断仍依赖模型，不构成文学质量保证。

应用层只调用一次审查，不自动重写正文或重复审查。审查期间释放数据库事务与游玩锁，允许用户继续操作。提案绑定故事包、路线正文与状态、意图版本及提示词版本；正文／意图变化、路线已有后续或被提前结束，都会阻止旧提案提交。审查迟到时保留审计结果，不覆盖新意图或提前结束回执；删除存档后不恢复记录。

提交在同一事务中保存提案 `committed`、终局回执和路线 `completed`。任一步失败整体回滚。提交后普通续写被既有结束状态校验拒绝；同一提案重复提交返回原回执。兄弟分支和历史祖先不因该叶分支结束而改写；从祖先重选仍产生独立后续。

自然终局回执记录 `ending_written=true`，含义是引用的已保存正文通过本次终局审查并已提交，并非提交接口又生成了一段文字。`route-closure` 和 journey 的 `route_health` 读取该回执；提前结束及无回执的旧记录不虚构自然终局正文。原规划中的 `ending_check.approved=false` 仍表示必要账本检查不能授予结束权限。

## 审计与重复请求

每份提案保留审查输入、原始响应、检查结论、失败原因、模型和提示词版本，以及调用次数、已报告 token、用量未报告次数和耗时。未报告用量不等于零成本。

同一分支的相同 `request_id` 和相同内容返回原提案；不同内容报 `request_conflict`。等待中的重复请求不再发起审查。被拒绝或失败的提案仍保留；明确重试需使用新的请求标识。进程在审查期间退出可能留下 `pending`，当前不会自动重试或判断供应商是否已计费；尚未提供自动恢复与永久费用账本。
