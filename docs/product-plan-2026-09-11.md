产品计划（2026-09-11）

状态：历史计划，已由 [2026-09-15 开发计划](next-development-plan-2026-09-15.md) 替代。旧的方向卡片预生成不等于当前要求的方向正文预生成；不再恢复已读原著、用户上传或从零创作等产品入口。

## 产品决策

产品收敛为单一核心体验：官方先获得一部完整的 10 万字以上长篇小说，再对小说进行解析、人工审校并构建故事包，用户以完全未知的读者视角进入故事，在阅读过程中通过预设方向或自由文本影响后续剧情。

用户不上传小说，也不在运行时从零生成小说。原始小说可以来自已获版权的外部作品，也可以是官方先行完成的原创作品；无论来源如何，`StoryPackage` 都只是完整原作的结构化解析、事实审校和互动规则标注结果。用户产生的是本局私有的分支连续性，不回写官方故事包。

这意味着产品的主要成本从“处理用户原著输入”转移为“官方长篇内容生产、审校、版本维护和分支质量维护”。

## 核心体验流程

```text
选择官方小说
  -> 了解少量开局背景
  -> 进入当前剧情拍点
  -> 同时展示已校验的剧情方向
  -> 用户选择方向或输入自定义行动
  -> 返回正文，图片异步生成
  -> 继续阅读、分支和收束
```

开局必须让第一次接触该小说的用户理解当前人物、地点、时间、已知事实和当前目标，但不能提前泄露角色尚未知晓的后续信息。

## 方向预生成

剧情拍点完成后，系统预生成 2～4 个下一步方向，并在展示前完成结构、状态、冲突和可达性校验。用户选择方向时直接使用已通过校验的方向结果，避免点击后才开始生成方向。

方向卡片至少包含：核心冲突、短期目标、潜在代价、预计推进的未解事项和下一剧情拍点。

已修订：每个可见预设方向出现时启动下一回合正文预生成，选中后复用已校验草稿；未选草稿不进入正式状态。任务、取消和成本规则以 2026-09-15 计划为准。

## 图片策略

图片是剧情的异步伴随内容，不阻塞正文、方向选择或下一回合。

- 图片绑定 `beat_id` 或场景 ID，不绑定每次自由文本输入。
- 新场景、关键人物首次出现、重大转折、小高潮和反转才优先生成新图。
- 正文返回时先提供占位、低清预览或已缓存图片；高清图在后台生成并替换。
- 用户离开场景后，尚未开始的图片任务可取消；已完成图片进入缓存。
- 图片失败、跳过图片或图片延迟不得改变权威剧情状态。

## 长篇剧情架构

官方小说按层级维护，不能依赖一次模型请求生成十万字正文：

```text
全书 -> 故事卷 / Act -> 故事阶段 / Arc -> 剧情拍点 / Beat -> 用户回合
```

每个层级维护目标、冲突、转折、完成条件和可用素材。运行时只加载当前拍点所需上下文，正文按回合生成并经过事实、状态和意图校验。

用户自定义方向必须经过“意图提取 -> 约束检查 -> 剧情方案 -> 正文验收”。正文需要体现用户的核心意图；如果无法执行，必须明确说明阻碍和可行替代路径。

用户严重偏离时允许形成新的私有分支。系统通过代价、人物动机、世界规则和未解事项使剧情重新获得因果，不强制恢复原剧情。

## 故事收束

系统维护开放线程账本，记录伏笔、人物关系、核心目标和预计回收拍点。每个 `Arc` 结束前应处理高优先级线程并产生阶段性结果。

终局由代码和官方包中的终局条件共同控制，至少检查核心目标结果、关键线程回收率和不可遗留冲突。模型不能单方面宣布结束，也不能在没有终局条件时无限续写。

## 官方内容维护机制

每部官方小说需要维护：

- 版本化 `StoryPackage`、剧情骨架和拍点索引；
- 世界事实、人物设定、关系变化和知识边界；
- 方向卡片模板、自由行动约束和终局条件；
- 伏笔与开放线程账本；
- 场景图片提示、人物外观约束和图片缓存；
- 每个版本的自动回归、真实模型抽样和人工试玩记录。

官方发布新版本时，已有用户会话继续绑定原版本；新会话使用新版本。不得静默改写已存在的用户分支。

## 分阶段实施计划

### 阶段一：原作小说资产 P0（当前优先级）

- 确定原作来源：已获版权的外部小说，或官方自行完成的原创小说。
- 完成一部 10 万字以上的完整原作；当前古典修仙提纲只能作为候选设计，不能替代原作。
- 当前先按官方原创路径推进《太虚遗录》原著创作，来源与版权问题暂不作为本阶段阻塞项。
- 冻结原文版本，记录来源、作者归属、权限范围、文件名和字节哈希。
- 对完整小说完成章节、人物、地点、事件、伏笔、剧情阶段和结局解析。
- 解析与人工审校通过后，从开篇制作前 1 万～2 万字可玩故事包切片。
- 详细内容资产见 [官方长篇小说 P0 规划：古典修仙](official-novel-p0-classical-cultivation.md)。

### 阶段二：产品边界收敛

- 删除用户上传入口和上传相关验收。
- 删除已读原著、节点介入和从零生成的产品入口。
- 将入口统一为官方小说书库与未知读者开局。
- 更新 `StoryPackage` 入口契约和 MVP 验收矩阵。

### 阶段三：方向与图片响应

- 实现方向卡片提前生成、校验、缓存和选择复用。
- 建立方向草稿与正式剧情状态的隔离。
- 实现图片异步队列、按拍点缓存、取消和失败降级。
- 记录正文首字节、方向可见、图片完成和用户跳过图片的延迟指标。

### 阶段四：长篇剧情运行时

- 固化 `Act`、`Arc`、`Beat` 层级和当前上下文装配。
- 实现自由文本意图约束、偏离代价和分支连续性。
- 建立开放线程账本、阶段性收束和终局控制器。
- 使用官方长篇样本完成至少三个连续回合和一个完整 Arc 的真实模型验证。

### 阶段五：官方内容生产与运营

- 建立官方小说的编写、审校、打包、发布和版本回滚流程。
- 为每部小说建立事实审计、图片审计和人工试玩记录。
- 以单部小说跑通从内容包发布到用户分支收束的完整流程，再扩展书库。

## 按优先级排列的开发清单

### P0：先建立唯一可玩的产品闭环

1. **统一产品入口**
   - 移除用户上传、原著已读节点介入和从零创作入口。
   - 只保留官方小说书库、小说详情和“开始阅读”。
   - 验收：新用户无需上传任何文件即可创建会话并进入第一拍点。

2. **定义官方长篇 `StoryPackage` 契约**
   - 增加全书、`Act`、`Arc`、`Beat`、人物知识边界、开放线程和终局条件的正式结构。
   - 明确官方包版本、发布状态和会话绑定规则。
   - 验收：包可独立校验；会话固定包版本；发布新版本不改写旧会话。

3. **完成未知读者开局**
   - 生成当前人物、地点、时间、必要前史、已知事实和当前目标。
   - 控制信息泄露，不能把角色尚未知晓的后续情节放入开局上下文。
   - 验收：第一次接触小说的人工试玩者能理解开局并知道下一步要做什么。

4. **建立剧情状态与正文的权威边界**
   - 保持 `RuleEngine`、事件追加、分支隔离和失败恢复规则。
   - 任何模型输出都不能直接改变权威状态。
   - 验收：模型超时、无效输出和重复请求均不会损坏会话或产生重复事件。

### P1：降低等待并保证用户意图有效

5. **方向卡片预生成与缓存**
   - 在当前拍点完成时预生成 2～4 个方向。
   - 在展示前做结构、状态、冲突和可达性校验。
   - 选择方向时复用已校验结果，不重复生成方向。
   - 验收：方向出现时已可选择；选择后不再等待方向生成；未选方向不写入正式剧情。

6. **自由文本意图约束链路**
   - 实现意图提取、硬约束识别、世界事实检查、剧情方案生成和正文验收。
   - 支持可兼容偏离、高代价偏离和不可兼容输入三种结果。
   - 验收：用户自定义方向的核心意图能在正文或明确阻碍中被验证。

7. **正文生成与短缓存**
   - 已修订：为每个可见预设方向提前生成下一回合正文；自定义方向在提交后生成。
   - 设置草稿状态、校验、父状态失效、过期、取消和成本上限。
   - 验收：正文首字节和完整正文延迟可观测；未采用草稿不会进入故事状态。

8. **图片异步管线**
   - 以 `beat_id` 或场景 ID 去重，建立任务队列、缓存、取消和失败降级。
   - 首先支持占位或低清预览，再替换高清图。
   - 验收：图片延迟不阻塞正文、方向选择或下一回合；跳过图片不影响剧情。

### P2：支撑长篇连续性与自然收束

9. **`Act` / `Arc` / `Beat` 运行时推进**
   - 将官方剧情骨架映射到运行时状态和上下文装配。
   - 只加载当前拍点所需内容，控制上下文长度和调用成本。
   - 验收：至少一个完整 `Arc` 能连续完成，且每个拍点都有可执行后继。

10. **开放线程与伏笔账本**
    - 记录线程来源、优先级、预计回收拍点、当前状态和回收结果。
    - 将人物关系、核心目标和未解事项纳入同一收束视图。
    - 验收：高优先级线程在 `Arc` 结束前有明确处理结果，不能只靠摘要宣称已解决。

11. **偏离分支的代价与重新获得因果**
    - 允许用户持续偏离，通过资源、关系、风险和新冲突维持因果。
    - 禁止无理由拼回官方原剧情，也禁止模型随意增加未确认事实。
    - 验收：严重偏离后仍能继续至少三个回合，并能解释偏离带来的后果。

12. **终局控制器**
    - 将核心目标、关键线程回收率、不可遗留冲突和终局候选条件写入代码校验。
    - 支持成功、失败和带代价的阶段性结局。
    - 验收：满足条件才结束；不满足条件不能突然结束；终局后不再接受普通行动。

### P3：官方内容维护与规模化

13. **官方小说生产和审校流水线**
    - 建立内容编写、事实审计、剧情图审计、图片提示审计、打包和发布流程。
    - 每个版本保存审校结果和人工试玩证据。

14. **版本与会话迁移策略**
    - 旧会话继续绑定旧包；新会话使用新包。
    - 只允许显式兼容迁移，不静默改写历史分支。

15. **成本、延迟和质量监控**
    - 记录方向生成、正文首字节、正文完成、图片完成、取消、跳过和失败指标。
    - 统计每回合模型 token、图片 token 和缓存命中率。

16. **扩展官方书库**
    - 单部官方小说完成 P0～P2 验收后，再增加第二部小说。
    - 新书必须通过同一套包校验、真实模型抽样和人工试玩门槛。

## 当前验收门槛

- 用户无需上传即可开始阅读。
- 首次进入能理解人物、处境和目标。
- 方向在出现时已经生成并通过本地校验。
- 选择方向后不重复生成方向。
- 图片不阻塞正文和下一回合。
- 自定义方向的核心意图在正文中可验证。
- 严重偏离有可解释结果，并保持状态和因果一致。
- 至少一个 `Arc` 能完成，关键线程得到回收。
- 终局由可持久化条件触发，不能无限续写或突然结束。
- 官方 `StoryPackage` 只读且版本化，用户分支可恢复、可追溯、互不污染。

## 暂不纳入

- 用户上传原著或任意文本导入。
- 用户从零构建世界和长篇小说。
- 已读原著用户的节点介入模式。
- 多种产品方向并行入口。
- 为每个用户输入生成独立图片。
