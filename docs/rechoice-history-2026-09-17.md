## 本轮修复

玩家回到旧节点点击“从这里重新选择”，再次选择同一个预设方向时，原实现仍按原来的 `preparedTurnKey` 查找已保存分支。结果可能返回已经结束的原路线，与界面承诺的“新的选择会开启另一条分支”不符。

现在显式重选会创建独立历史标识。预生成、方向提交、自定义行动和幂等回执共同绑定它；原路线及其结束标记、收束回执、正文和状态不受影响。普通恢复已生成结果继续沿用原有复用行为。

## 行为与接口

- `PrepareChoicesRequest`、`PlayContinueRequest` 新增可选 `history_id`，支持 JSON 和 SSE 提交；有效值为非空字符串，最长 200 字符。
- 桌面只在点击“从这里重新选择”时分配标识。同一次重选的轮询、预生成和提交保持相同标识；切换阅读分支后清除。刷新尚未提交的重选页会回到普通回看，再次显式重选会分配新标识。
- 新标识参与草稿和已保存结果的绑定，不改变父分支内容或权威状态摘要，不作为用户行动发送给模型。只读取该父节点及其祖先历史，不继承被放弃的后代结局。
- 同一次重选仍只预生成当前一层方向。进入新分支后，按新分支 ID 继续常规游玩；不递归预生成后代。
- 重选同一个预设方向也会生成新历史，因此可能产生新的模型用量；同一历史内重复点击、轮询及响应恢复不会重复生成。不同历史不能复用旧草稿；旧请求标识不能改绑另一历史。
- 新标识不授予绕过终局、事实、状态或故事包校验的权限。已结束节点本身仍拒绝预生成和续写，需要回到更早的有效节点。
- 未传 `history_id` 的旧调用保持兼容。恢复同一请求的结果，不视为开启新历史。

## 验证

测试自动枚举全部达标官方长篇；当前为《太虚遗录》第一部，102610 CJK，`taixu-relics-part1@0.1.2`。只使用临时数据库和官方长篇夹具，不执行退役短篇。

新增 `tests_api/test_longform_rechoice_history.py`，6 项测试覆盖：

1. 原路线提前结束并重启后，同一预设方向产生独立、可继续的兄弟分支；原正文和结束回执保持不变。
2. 预生成、轮询、选择与重启共用当前历史；另一重选历史生成不同分支，没有预生成后代。
3. 请求标识与历史绑定，跨历史复用请求或旧草稿被拒绝。
4. 自定义行动保存历史标识，但生成器收到的仍只有原始行动。
5. 模拟每次生成 17 tokens：原路线与新路线各展示一次，共确认 34 tokens；未选方向仍归入 `display_unconfirmed`，重启和重复阅读不重复计量。
6. HTTP/SSE 端到端透传与输入校验。

## 验收边界与后续

本轮没有外部模型调用，没有修改生成提示词或进行真实长篇终局试玩。NQ-001、END-001、SRC-001 继续暂缓，不能把新分支工程测试视为自然终局或叙事质量通过。

用量验证仍限于保留中的草稿尝试，不是永久成本账本。图片统计尚待下一批核查：`illustration_metrics.report` 总计与展示分组对非法 token 回执的校验不一致，需要统一非负、有限数值与未知用量口径。本轮未修改图片统计。
