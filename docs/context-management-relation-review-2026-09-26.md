- 脚本只从被显式标为 `player_known` 或 `public_world_fact` 的叶子读取玩家位置。审核投影可见的其他内部字段不因此成为公开证据；物品归属和隐藏状态不进入输出。

- 公开 `playerLocationId` 与玩家对应的 `characterLocationIds` 若冲突，直接报错，不选择其中一个放行。比对结果包含快照、分支、来源路径和值；即使字段匹配，`proseAcceptance` 也固定为 `false`，因为尚未验证正文到结构化命题的转换。
- 对照标签、标注理由和预选来源不进入未来核对请求的构造函数。本轮只完成这一输入隔离检查，没有调用模型或增加提示。
- [回归测试](../tests_py/test_context_relation_audit.py)覆盖隐藏字段、冲突状态、过期快照、旁支、条件/时间丢失、未知对象、伪造模型依据及来源篡改。

## 关系语义审核

| 关系 | 对照 | 标注边界 |
| --- | --- | --- |
| 位置 | 伤者在同一封山线外 / 内 | 公开来源明确线外；同一时点内外相反 |
| 否定 | 伤者活着 / 已死；尚未登记 / 已登记 | 来源有明确肯定或否定，不用“没记录”代替否定 |
| 主体 | 陆沉舟三年前离开 / 守门弟子三年前离开 | 后者缺证，不能推出守门弟子从未离开 |
| 时间 | 三年前离开 / 两年前离开 | 没有唯一事件标识，不能排除多次离开；后者缺证，不直接判矛盾 |
| 完成 | 说要押送 / 已完成押送 | 意图不能证明完成，也不能证明未完成 |
| 先后 | 押送后失踪 / 失踪后才押送 | 未确认两句指向同一且唯一的一组事件，后者缺证，不用词序机械判互斥 |

下一阶段若做事件关系比较，事件身份与时间范围必须成为核验前提；单独比较时间词、否定词或“内/外”不足以给出可靠结论。

## 修复与复审

首次原型检查发现：对没有解析到的对象 ID 直接做字符串不等比较，可能把未知地点的否定命题判为支持。已修复为对象 ID 必须出现在已验证的公开位置事实中，否则 `needs_review`；地点中文名称也不能未经解析就当 ID 使用。补充正、负两个极性的回归，复审通过。

保留[首次离线报告](evidence/context-management-2026-09-22/context-relation-audit-2026-09-26.json)，最终代码对应[修正后报告 v2](evidence/context-management-2026-09-22/context-relation-audit-2026-09-26-v2.json)。两份均为 0 次模型调用，控制用例计数相同；未知地点修正的证据由新增回归承担，不能用计数未变声称旧实现已经正确。

最终相关测试 70/70 通过。核心回归 244 项中 243 项通过；唯一失败仍是既有 `consequences.plan` 提示哈希基线，未修改基线掩盖失败。本轮没有 API/前端改动，未重复运行其回归。
