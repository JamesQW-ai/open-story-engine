## 实现及职责边界

- [新实验脚本](../test_support/context_indexed_pipeline.py)按原文标点生成单元编号、段号与字符起止位置，直接从原稿绑定 `quote`。逗号等机械边界不是语义边界，不声称自动完成原子命题拆分。
- 提取仅收到当前 `draft` 和程序生成的 `units`，返回每个编号下的 `statements`。一个单元允许多个命题，不要求模型重新抄写引文、计算位置或做互斥字符分区；模型不得覆盖这些程序字段。
- 忠实度检查只收到原稿、单元和全部对应命题，核对原意及覆盖完整性。它不接收玩家意图、公开证据、预标答案或旧审核。`lossy`/`uncertain` 都停止该例，不进入来源核对，也不自动修稿。
- 来源核对只在忠实度通过后运行，收到原稿、玩家当前动作、提取命题和过滤后的公开来源。它不能输出 `extraction` 或修改命题，不接收忠实度理由、历史正文、完整 bundle 或隐藏权威状态。
- 三份实验提示：[提取](../test_support/prompts/context_indexed_extract.md)、[忠实度](../test_support/prompts/context_indexed_fidelity.md)、[来源支持](../test_support/prompts/context_indexed_support.md)。旧两阶段脚本和提示保留供复现。
- 复用已验证的评分与原子检查点实现。多个命题共享同一定位且出现拒绝时，额外标记 `ambiguous_rejection`/`requiresReview`；不能用引文重叠替代对具体命题的判断。兼容评分器的 `faithful` 字段仅在独立忠实度全通过后由适配器填入，不覆盖任何失败结论。

本轮将最多两次请求调整为最多三次，仅作为诊断实验：上轮已有两条忠实度/来源判断混淆，第三次请求用于检验输入隔离。每例单次提取、单次忠实度、单次来源支持，总上限 36；未证明额外调用的收益足以支持生产采用。

## 真实结果与语义复审

证据：[原始请求与响应](evidence/context-management-2026-09-22/context-indexed-pipeline-2026-09-26.json)、[离线复算与语义发现](evidence/context-management-2026-09-22/context-indexed-audit-2026-09-26.json)。固定集、期待值和目标引文保持不变；没有为取得通过而扩大原来的目标标签。

| 样本 | 机器结果 | 复审结论 |
| --- | --- | --- |
| `recorded_v11` | `unexpected_rejection` | “胸口还在动”被拒绝；侧身、皱眉等正常姿态却因无历史记录被误拒。其他位置或动作须独立标注，不能把所有额外拒绝一律归为误报 |
| `supported_life` | `matched` | 存活与持灯关系得到公开来源支持 |
| `ordinary_action` | `false_positive` | 玩家明确授权点头和等待，仍被要求历史证据，是明确误报 |
| `legal_wait` | `matched` | 请求和等待被正确保留；与上一项的边界判断不一致 |
| `honest_unknown` | `matched` | 承认未知与“你说”动作分别处理；未再要求动作单元重复台词 |
| `supported_negation` | `matched` | 未登记状态与来源一致 |
| `reported_history` | `matched` | 保留离开及声称押送的区别；时间片段与主句存在重复恢复事件的情况，仍需改进单元职责 |
| `derived_symptom` | `matched` | 正确拒绝从存活状态派生具体胸口起伏 |
| `negated_life` | `matched` | 正确识别死亡与存活的直接矛盾 |
| `swapped_subject` | `unexpected_rejection` | 除预标的离开事件外，押送意图也被错误归给守门弟子；额外拒绝有合理依据，不是误报 |
| `expanded_permission` | `unexpected_rejection` | 条件片段和主句各恢复相同完整规则，两次拒绝都合理；暴露重复提取及目标定位不完整，不是两个独立违规 |
| `reported_to_completed` | `unexpected_rejection` | 时间片段被提取成无事件对象的“时间限定为三年前”，且被忠实度放行；来源核对误解其范围。完成断言被拒绝，但把缺证误称为 `contradicted`，应为 `unsupported` |

7 `matched` 只表示当前程序的结构与定位评分，不能叫整套方案准确率；正例 5/6 机器匹配，反例 2/6 机器完整匹配。六个反例都有目标定位命中，但其中四个还包含额外拒绝。不能据此宣布“零误报”或“语义准确率 100%”。

忠实度模型本轮全部给出 `faithful`，这并不能证明全部提取都合格：“时间限定为三年前”仍缺少完整事件对象，条件与主句也会重复同一个命题。程序固定位置解决了重抄问题，尚未解决语义单元设计。

## 下一步
