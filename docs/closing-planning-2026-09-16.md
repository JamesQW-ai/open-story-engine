## 冻结上下文与任务绑定

`SessionStore.closing_intent` 只解析选定祖先链的最近意图；`TurnSnapshot` 保存其副本，业务核心把副本作为 `closingIntent` 传给规划器。正式正文、状态账本和历史分支不因此被改写。

每次实际修改或撤销意图分配新的 `revision`；重复提交相同意图保留版本。旧记录首次登记会补上版本。缓存绑定新增 `closing_digest`，覆盖意图、登记分支及版本，因此正常→失败→正常也不会重新激活最早那份草稿。

- 获取冻结上下文后、准备方向入队前、自定义行动入队前、正式提交事务内均使用当前绑定校验。
- 意图变化使旧任务过期，返回 `draft_expired`，不再误报路线已结束；已经绑定当前意图的并发任务保留。
- 另一服务实例持有旧任务时，提交仍被数据库中的当前绑定拒绝。远端实例已发出的模型请求不保证立即中止，可能产生未采用用量。
- 旧菜单传回的 `draft_id` 在生成前拒绝。兄弟分支的局部意图修改不影响其他分支；重启后的同一版本仍可得到一致绑定。
- 提升草稿规则版本以隔离旧上下文。已保存正文继续可读；不承诺在新规则下复用旧规则生成的缓存。

## 结果规划与终局条件

`reader_consequences.planning_context` 新增 `closing`。无意图或显式撤销时为 `null`；有效意图包含类型、阶段、登记分支、`ending_check` 与边界说明。既有 `closure.outstanding` 继续提供待交代条目。

结果规划提示词明确：收束意图不是额外行动授权，不得为了收束擅自放弃目标、制造死亡、推进时间或补造未知事实。本回合仍只提交既有契约允许、经过原有审查的变化；没有增加模型调用、审查轮次或终局写入权限。

`ending_check` 是必要账本条件，不是语义终局验收：

| 类型 | 本批核对的必要条件 |
| --- | --- |
| `normal` | 清单通过，已登记目标都有完成依据；有依据放弃不能算完成 |
| `deviation` | 清单通过，存在有依据的目标放弃或转化；后继目标仍由清单独立核对 |
| `failure` | 清单通过，至少有未达成而放弃的目标依据；主动放弃仍不证明因果上的失败 |

缺失历史、账本损坏或未知目标范围不能通过。`ledger_ready=true` 只表示这些必要条件满足，仍固定 `outcome_review_required=true`、`approved=false`。阶段 `closing` 仍按清单计算，不能代替某种结局类型的条件判定。
