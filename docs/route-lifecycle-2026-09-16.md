本批实现 P6 收束阶段与结束类型的后端契约。收束意图是玩家希望如何结束的记录，不能作为剧情已成功、已失败或结局已写成的证据。NQ-001 与 SRC-001 继续暂缓。

后续进展：收束意图已接入结果规划及草稿绑定，见 [收束规划接入记录](closing-planning-2026-09-16.md)。下文保留本批交付时的验证范围。

## 接口与阶段

写模式新增 `POST /api/v1/sessions/{session_id}/route-closure`：

```json
{"branch_id":"当前路线末尾的分支 ID","intended_type":"normal"}
```

`intended_type` 支持 `normal`（正常收束）、`deviation`（偏离收束）、`failure`（失败收束）和显式 `null`（撤销）。字段不可省略。`early` 使用已有 `POST .../end`，不能通过登记意图冒充已结束。只读模式不开放写接口。

已有 `GET .../route-closure?branch_id=...` 增加 `lifecycle`：

| `phase` | 条件与含义 |
| --- | --- |
| `active` | 尚未登记收束意图，或已明确撤销。清单为空也不自动开始收束 |
| `preparing` | 已登记意图，但清单仍有待交代事项、依赖阻塞或未知状态 |
| `closing` | 已登记意图且清单通过，可以进入结局创作与验证；仍允许普通游玩，仍不表示已结束 |
| `ended` | 既有路线状态已结束，不能重新登记收束意图或普通续写 |

阶段根据选定分支的最新清单计算。如果收束中新增开放问题，会回到 `preparing`。`intended_type` 与实际 `ending_type` 分开；本批实际结束类型只写 `early`，自然结束类型必须等待独立的结局证据契约。

`requires_ending_evidence=true`、`ending_written=false`。正常／偏离／失败三类目前只是意图，尚未执行各自的成功条件或自然终局验收，不能借 `closing` 标签推断目标达成。

## 持久化与路线隔离

- 新增 `route_lifecycle` 表，按存档和分支保存意图及提前结束回执，不修改既有正文、状态账本或局部大纲。
- 意图沿当前祖先链继承；子分支的修改／撤销只影响该分支及其后代。显式撤销会遮蔽继承来的旧意图，不删除祖先记录。
- 仅允许在路线末尾登记或撤销，已有后代的节点拒绝修改，以免追溯改变已游玩分支的意图。
- 重启后可恢复，重复登记结果相同；删除存档会一起删除其收束记录，不影响其他存档。
- 旧库没有新表时，只读接口返回没有登记意图，不初始化或迁移数据库。旧结束记录没有回执时保留 `ending_type=null`，不补造历史。

## 提前结束

`POST .../end` 继续返回原有 `status=abandoned`，同时保存 `early` 回执，包含结束时间、结束前清单状态、覆盖范围、未交代及已交代条目。回执通过 `GET .../route-closure` 的 `lifecycle.receipt` 读取。

回执与结束标记在同一个 `BEGIN IMMEDIATE` 事务中写入；失败一起回滚。重复结束保留首次时间和清单。提前结束不把未完成目标改成已完成，也不把预设的失败收束意图改写成已证明的失败结局。

账本损坏时仍允许提前结束，回执明确记为 `readiness=unknown`、全部覆盖范围 `unknown`，空列表不能当成已解决；损坏历史的收束读取仍可能返回受控 `409`，本批不自动修复历史。

结束后继续沿用既有生成任务取消、准备／提交阻断。新增数据库事务使另一个服务实例的迟到提交也必须在获得锁后检查结束状态。
