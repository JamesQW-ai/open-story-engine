## 本轮范围

接续道具永久损毁约束，为目标和开放线程增加明确的道具依赖，并接入局部大纲、收束准备和路线监测。原先目标只登记人物依赖，线程没有道具依赖，原物损毁后无法在任务层显示对应阻碍。

## 行为与契约

- `goalUpdates` 和 `threadUpdates` 可声明 `itemDependencies`，引用已登记的原著或衍生道具 ID。数组须无重复，最多 16 项；人物 ID、未知 ID、非数组不接受。
- 更新旧条目时省略字段表示继承，明确 `[]` 才表示解除道具依赖。新增、替换和解除都沿用现有逐项正文证据检查；仅依赖改变的更新不会被当作“状态没变”丢弃。没有该字段的旧存档不自动推断依赖。
- 不能新建或更新一个继续依赖永久损毁原物的进行中目标、后继目标或开放问题；同回合即将损毁的原物也在检查范围内。既有依赖失效时允许保留旧记录等待玩家决定，不要求在损毁回合擅自放弃任务。
- 局部大纲为有来源的目标和线程生成道具阻碍，下一步改为 `review_dependency`。条目本身保持 `active` / `open`，不自动失败、完成、解决或放弃。改换路径须有新证据，放弃或关闭仍保留原依赖历史。
- 阻碍的损毁证据只来自当前祖先链，并核对对应道具变化、正文引文及损毁状态。只有标记却没有本路线证据时使用 `unknown`，收束准备进入 `blocked_unknown`；有证据的受阻依赖进入 `blocked_dependency`。
- 收束清单同时列出目标和线程的道具阻碍；规划输入及动态方向上下文携带相同依赖。过滤受阻目标的旧“推进目标”备用方向，玩家仍可自定义行动。
- 路线监测计入道具依赖变化，解除或更换依赖不再误算为状态停滞；仅调整数组顺序、给旧记录补空数组不算推进。
- 大纲、收束与监测版本更新为 `/2`。接口保留人物冲突结构，新增道具冲突结构，包含 `target_kind`、`target_id`、`item_id`、`status` 和证据。旧存档的大纲只读重建，不做迁移写入。

## 验证结果

新增测试通过 `longform_cases()` 枚举全部十万汉字以上官方长篇。当前只有《太虚遗录》第一部，102610 CJK，`taixu-relics-part1@0.1.2`。没有执行退役短篇。

| 检查 | 结果 |
| --- | --- |
| 新增长篇道具依赖专项 | 8 项通过 |
| 依赖约束 | 非法引用、同回合损毁、后续新增依赖被拒绝；依赖调整须有正文证据 |
| 账本与保存 | 临时数据库保存重开后依赖保留，原分支无新增阻碍；省略字段继承，关闭保留历史，转化后继目标须显式解除失效依赖 |
| 证据与未知 | 未经来源支持的依赖修改降为未知；损毁缺证据时不虚构原因或清单通过 |
| HTTP 只读 | 返回目标与线程的道具冲突，禁止初始化写库，数据库字节不变 |
| 路线监测 | 实际依赖变化记为目标／线程变化；重排和补空值不伪造进度 |
| 当前 API 回归 | `.venv-api/bin/python -B -m test_support.run api`：416 项通过 |
| 当前核心回归 | `python3 -B -m test_support.run core`：25 项通过 |
| 差异 | `git diff --check` 通过 |

验证中修复了旧方向上下文被多加空字段的兼容性问题。收束版本断言随版本更新；`consequences.review` 的有意契约扩展按现有规则移出最初迁移的逐字比较，保留原始提示词基线，不重写历史摘要。

## 文件与边界

实现涉及 `item_lifecycle.py`、`reader_consequences.py`、`reader_threads.py`、`reader_choices.py`、`route_outline.py`、`route_closure.py`、`route_monitor.py` 和 `api_models.py`。提示词补充位于 `prompts/consequences/{plan,review,threads_plan}.md` 与 `prompts/reader/choices.md`。新增专项为 `tests_api/test_longform_item_dependencies.py`。

本轮没有外部模型调用、正式存档改写、前端代码修改或桌面浏览器验证。已有桌面收束视图可以消费清单的通用条目，但本轮不据此宣称完成视觉验收。

程序只约束已登记依赖，不从目标标题推断缺失字段，也不能保证模型不漏报或不错误解除依赖。证据绑定证明记录来自本路线正文，不等于语义判断已经通过真实模型验收。后续可对“建立道具依赖 → 损毁后保留待复核 → 用户改换路径”做有限真实模型契约验证，记录首轮失败，不回到反复修改正文质量的循环。NQ-001、END-001、SRC-001 继续暂缓。
