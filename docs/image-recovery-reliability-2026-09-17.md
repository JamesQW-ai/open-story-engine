## 问题与修复

上轮已让图片统计保留损坏／缺失用量为未知，但图片恢复接口仍按宽松的缓存读取方式判断是否可生图：损坏 JSON 被当作无记录，非对象 JSON 可能触发异常，缺少调用数可能被当作零调用。已完成记录对应的图片文件丢失时，接口还可能返回 `ready`，或在真正下载时产生服务器错误。

本轮在 `api_illustrations.py` 统一恢复判断，保留原始文件，不自动修复记录或再次计费：

| 情况 | 恢复行为 |
| --- | --- |
| 损坏 JSON、非对象、绑定 key 不符、未知任务状态 | 返回 `failed`，不能重新生图 |
| 调用数缺失、非法，或零调用与状态／用量矛盾 | 返回 `failed`，不能将未知当作零调用 |
| 只有图片文件、缺少任务记录 | 返回 `failed`，保留孤立文件，不再次调用 |
| 重启遗留排队／生成中任务，已记录调用 | 返回 `cancelled`，缺失回执仍为未知，不重新调用 |
| 重启遗留排队任务，明确零调用且无矛盾回执 | 可显式重新生图；随后同分支请求继续复用 |
| 已完成记录缺少图片文件或有效 MIME | 返回 `failed`，没有图片 URL，也不允许再次生图 |
| 已完成记录和图片均可用 | 重启后继续复用，可正常记录展示 |

图片下载与展示回执使用同一可用性判断。不可用的私人图分别返回 `404 illustration_not_ready`、`409 illustration_not_ready`，不写展示回执。判断同样覆盖服务仍在运行时图片文件被移除的情况。

审校公共图的展示优先级也与查询保持一致：公共图可用时，展示回执归属 `published`，不会把已有私人图片的用量误归为已展示；公共图不再适用且私人图可用时，才确认私人图展示。

## 边界与下一步

本轮未修改前端，沿用已有 `failed`／`cancelled` 展示；没有真实模型或图片供应商调用，不代表真实连续阅读质量验收。NQ-001、END-001、SRC-001 继续暂缓。

恢复检查验证记录结构、调用边界、文件存在和 MIME 声明，不是逐张图像内容审校，也未建立永久费用账本。若任务记录与图片全部被外部删除，现有缓存无法证明历史调用；跨进程同时生图的全局去重仍未实现。

下一步可独立核查审校素材清单的异常降级与兼容性检查，确保坏素材不影响阅读接口，也不绕过人物／道具状态约束；不扩展自动配图规模。
