## 目标与现有基础

在已审核正文的关键高潮处配上当前分支适用的名场面预设图，或者实时生成；正文过长时在自然段落边界插入图片辅助阅读。图片不得泄漏未到达剧情或表现正文没有成立的事件。

复用 `open_story_engine/api_illustrations.py` 的现有图像接口、队列、缓存、订阅取消及展示记录，以及 `web/src/components/StoryProse.tsx` 的正文渲染。保持原图像服务地址和路由，先做客户端提示与请求调度优化。

目前 `long_scene_policy` 对非开场且达到 700 CJK 的正文允许手动生图；实际请求取正文开头 500 字作画面材料。前端把图片放在阅读分节的中间，全部图片共用这个位置。此实现未绑定高潮发生的段落，也不能证明图中时刻与插入位置一致。现有预设素材清单校验只证明文件完整性，不证明视觉和剧情匹配。

## 开发顺序及验收

| 顺序 | 工作项 | 最小实现 | 通过条件 |
| --- | --- | --- | --- |
| I1 | 定义插图位置 | 以已提交正文的版本/哈希建立稳定段落 ID；记录目标段落、画面所在时刻、触发原因、包版本和分支 | 同一正文重载位置一致；正文改变时旧定位失效；不在对话句中间切开，不改变正文内容 |
| I2 | 决定是否需要图 | 优先采用已审核场景计划的高潮标记，并核对事件已在正文中实现；长正文在无图的连续文本超过阈值时，选择附近自然场景断点 | 超长文本有阅读分隔，短文本不强插；同一个高潮与长度触发合并，首版每回合最多一张新增图；阈值用真实桌面阅读样本校准 |
| I3 | 预设与实时路由 | 先找包版本、已发生事件、角色和当前分支状态均兼容的名场面图；偏离原剧情或无匹配资产才进入实时生成候选 | 不因源章节相同就套用原剧情结果；无适合画面时允许略过；复用失败不自动花费新的生成请求 |
| I4 | 优化提示 | 从目标段落与已公开外观资料组装主体、动作、环境、构图、统一画风和禁止项；引用来源仅进入审计，图片提示不追加整段历史 | 提示与插图时刻一致；人物、服饰、道具、天气不冲突；隐藏事实和未来剧情为零；同场景提示版本可追溯 |
| I5 | 优化出图耗时 | 缓存键含场景/可见状态/提示版本/模型参数；同键请求合并，预设资源预取；实时图在正文审核提交后异步生成；切分支或取消订阅即撤销无用任务 | 正文首字不等待图片；重复打开无重复生图；迟到结果不能插入另一分支；失败保留正文，无无限重试 |
| I6 | 接入段落渲染 | API 返回图片与段落锚点，前端就近插入并保留原有开场图、历史回放、一次展示及取消规则 | 长正文、高潮、回看、流式结束、返回/切分支场景均正确；加载和失败不会造成大幅滚动跳动 |
| I7 | 实测与上线判断 | 先用全部达标官方长篇做确定性与桌面回归，再用小批真实接口配对实验验证提示/尺寸参数 | 同时报告画面匹配、人物一致性、无剧透、请求数、缓存命中、队列/服务端/下载/展示 P50 与 P95；质量不降且耗时有证据改善才启用新参数 |

I1 的建议结果字段为 `branchId`、`proseSha256`、`afterParagraphId`、`paragraphSha256`、`sceneMoment`、`reason`、`sourceMode`、`assetId` / `jobId`、`promptVersion`；这是待实现契约，不表示现有 API 已提供。保持工程字段在内部，不在阅读界面展示审核信息。

I4 首版使用本地确定性提示组装，不增加每回合串行语言模型调用。只有局部段落无法明确形成单一画面时才保留不生成的结果，后续再用实验决定是否需要独立画面规划模型。

I5 的速度收益需分开看：预设/缓存可直接减少生成请求，实时提示精简主要降低无关内容与图文错配，未实测前不声称显著缩短图像模型推理时间。先保留当前质量规格；尺寸、质量档位或模型调整采用同画面配对测试，不以低质小图或更快失败充当优化。
