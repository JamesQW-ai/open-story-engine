## 审核发现与修复

发现 P1：`_turn_snapshot` 虽然每次读取 lineage，但缓存键只绑定父节点、合同、衍生包和收束意图。临时官方长篇会话中修改根节点摘要、保持当前父节点不变后，复现 `bindingUnchanged=true`、`snapshotReused=true`、`staleAncestor=true`。这意味着旧快照可能覆盖刚读取的历史；仅检查父节点的草稿提交也无法识别这类祖先变化。

处理：

- `lineage_digest` 按顺序散列每个节点的完整规范 JSON，再对各节点摘要形成整条链摘要。每次只分配单节点的 JSON，不拼接整条链的大字符串；未删除或摘要化任何校验字段。
- 回合绑定加入 `lineage_digest`，快照缓存因祖先变化而失效。入队和提交重新计算并比较；不接受缺少该字段的旧绑定。
- `RULES_VERSION` 从 `prepared-player-turn/22` 升为 `/23`，避免旧准备结果在新校验规则下继续使用；不迁移或删除已保存分支。
- 入队、提交中的路线状态和收束检查复用同事务已读取的 lineage；提交的路线大纲也复用它。自然结局保存等后续逻辑保持原有事务边界。

回归覆盖：祖先变化产生新快照；先前返回的快照保持原内容；兄弟分支变化不影响当前路线；旧草稿不能入队或提交；拒绝提交前后临时库逻辑转储相同；无历史摘要的旧绑定失败关闭。既有收束变更、已结束路线、并发与幂等测试继续执行。

本轮修复的是来源变化后的失效机制，不代表历史来源本身已经通过语义审核。

## 历史字段依赖与方案取舍

| 消费环节 | 当前依赖 | 对读取优化的约束 |
| --- | --- | --- |
| `module_context` / `ContextBundle` 连续性 | 最近两段已提交摘要 | 可有界注入，不需要把全链正文送给写作模型 |
| `reader_scene_review` 历史证据 | 最近三个已提交摘要和已审阅入口事实 | 不把旧正文注册为新正文的权威证据 |
| `dynamic_memory.select` | 完整祖先关系、来源正文/意图/审核凭据、历史物品状态变化、当前账本 | 不能仅截取最近 N 回合；否则可能复活已失效记忆或错过 A→B→A |
| 后果规划 / 收束 / 路线大纲 | 当前账本和祖先因果记录；规划中最近三个关键后果及最近三回合 | 不能直接将全局 lineage 替换为短窗口 |
| `reading_history` 兼容/审核路径 | 最近两回合详细摘要，较早回合短摘要，最终限 5000 字符 | 不等同于新 bundle 的相关性选择；后续需审计各调用点，不能宣称全部旧历史路径已替换 |
| 草稿绑定与提交 | 完整有序祖先链 | 优化后来源变化仍须立即使旧草稿失效 |

本轮决定不做数据库迁移、不引入有损历史摘要、不跨请求缓存校验结果。检查点/增量存储现在涉及太多消费者，先做更小的读取侧原型比较。

## 后续开发清单

1. **优先减少重复序列化**：研究同一次数据库读取中生成历史指纹，避免在解析完成后再次规范序列化整链。指纹必须覆盖持久化内容和实际会话/序号绑定，保留顺序、断链、循环、跨会话检查。先在临时库配对原型中验证，不直接修改正式历史。
2. **验证替代读取的等价性**：在 32/128/512 回合比较绑定失效行为、全部 lineage、来源选择、生命周期审计、bundle/写作投影；覆盖历史节点变化、JSON 格式变化、兄弟分支、旧版本凭据和回滚。格式变化造成保守失效可接受，内容变化漏失效不可接受。
3. **需要时再设计历史存储压缩**：仅当读取侧优化后仍有明确瓶颈，再提出完整可还原的检查点/增量格式及旧库兼容方案，单独审核迁移；不得靠忽略字段获得性能数据。
4. **恢复质量主线**：审计 `reading_history` 的写作/修复回退路径与 bundle 的差异，完成语义纠错/候选拒绝契约，再做有界真实正文—审核—修复—提交验收。不能用离线吞吐替代质量验收。
5. **最后接入剧情配图**：按已约定的关键剧情/长文分隔策略，接入既有图片接口并优化提示与延迟。
