## 本轮实现与边界

- 独立背景核对由整段一句判定改为程序划分的逐句单元 `P1-C1` 等；仍携带完整正文以保留说话者、引号和上下文。每句必须覆盖，区分当场反应、承认未知、既有背景、依赖具体观察的推断。
- 背景与推断判定通过时须给出公开资料的原文来源；代码拒绝不存在的来源 ID、假引文和缺来源的肯定判定。来源语义是否充分仍依赖模型，代码不会将“同一物品”当成“同一事实”。
- 独立审查收到程序从原始输入拆出的全部要求，而非规划器改写后的摘要；逐句记录违反的要求，并在全文读完后汇总。若综合判定“满足”，但逐句指出了违例，仍拒绝正文。
- 对含“只／仅”的排他要求，额外执行一次范围专项核对。输入只有用户原话、待查条款和正文，要求先列出反证，再判断是否满足。代码验证反证来自对应正文段落；存在有效反证时，`satisfied` 汇总也不能覆盖它。其他要求仍由原有行动审查和独立复查共同覆盖；关键词仅决定是否增加专项核对，不承担放行规则。
- 背景问题、范围问题与第一轮行动／连续性／状态问题合并后送修；修复后重新核对整篇。相同回合、逐字相同的正文复用独立核对及专项结果，改过正文必须重新检查。未提高原有三轮正文和每回合 18 次底层调用上限。
- 审计新增 `independent_review_result`、`scope_review_result`，保留具体判定与来源；沿用上轮修复前后正文和失败原因记录。仅引用格式有错时不能掩盖同轮其他明确的语义拒绝。
- 写作输入突出用户原始条款；提示词明确：只看指定物品不得顺便检查另一件，未打开的包裹不能产生内部视觉依据，不用新线索填字数。

本轮主要文件为 `reader_scene_review.py`、`api_narrative.py`、`reader/scene_grounding.md`、`reader/scope_review.md`、`reader/narrative_system.md`、提示词 manifest 及三份相关 API 测试。没有扩展 P4、图片或手机端，也没有修改主存档、母本故事包或现有前端。

## 固定旧稿回放

使用上轮保存的完整正文与当时可见的公开前情，额外加入一份明确不交物、不离开、只看纸包、回答“不知道”的正确对照。所有中间结果均保留，不能用最终成功覆盖前面的漏报。

| 检查方式 | 结果 | 限制 |
| --- | --- | --- |
| 第一次逐句＋范围综合核对，4 次调用 | 旧告知被拒绝；较早询问拒绝；最终旧询问仍误放行；正确对照通过 | 告知还存在引用当前正文为来源的格式错误；旧询问的“转看木牌”未拦下 |
| 调整为先逐句后汇总，2 次调用 | 最终旧询问的新增刻痕深浅、接触方式和成因被拒绝；正确对照通过 | 同一份旧稿的“转看木牌”仍漏报，不能宣称行动范围已修好 |
| 独立范围专项，2 次调用 | 旧询问准确定位 P9、P10、P13 的转看木牌；正确对照通过 | 仅一组正反样本，分别约 3.78 秒、2.73 秒，不代表长期稳定性 |

这说明检查任务混在一起时会漏掉相互独立的限制。专项核对已接入，但会增加调用，整体成本必须由真实连续测试衡量，不能仅凭单次专项很快就宣称提速。

## 连续测试口径

沿用同一正式角色、同一开局父分支和三条原始输入，模型为配置中的 `deepseek-v4-pro:cloud`。每批使用主数据库的独立备份，成功后接续最新分支，失败不推进。调用 `PlayService.continue_turn` 并监听流式回调，属于服务层真实模型测试，不是本轮新增的浏览器连续试玩。

汉字数按 `[\u3400-\u4dbf\u4e00-\u9fff]` 统计；首片段时间为服务层首次正文回调，完成时间包括复查、修复和提交。tokens 为供应商报告的全部输入输出量。不同版本不合并计算成功率；三次写入成功不等于三类正文质量通过。

中间版本的告知为 736 汉字、67.03 秒、8 次调用、37441 tokens；询问为 519 汉字、162.96 秒、15 次调用、120954 tokens；简短等待为 249 汉字、29.36 秒、8 次调用、48424 tokens。询问最终没有转看木牌，明确无法判断来历，但多轮重写后篇幅不足，且等待篇幅较短。告知仍有“药圃不算大”等需要核查的断言，因此不能算质量通过。
