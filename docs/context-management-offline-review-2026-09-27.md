| 层 | 已有实现及证据 | 尚未完成 |

| 动态记忆 | 字段、来源校验、纯迁移守卫；未确认记录不进入写作/修复投影；摘要不能升级为事实来源 | 审核凭据、来源语义充分性、事务写入、版本冲突处理、下回合装载、长期检索与失效闭环 |

直接代码依据：`ContextBundleBuilder.build()` 默认 `dynamic_memory=()`；`LlmPlanner._build_context_bundle()` 的实际装配调用没有传入该参数；`validate_dynamic_memory_transition()` 自身注明为未来 writer 提供纯校验，目前无生产调用。它也不证明 `candidate → confirmed` 有足够语义依据，或跨分支继承内容确实未被篡改。不能把这些结构能力称为动态记忆生产闭环。

新增 `tests_py/test_context_memory_longform.py` 使用 `longform_cases()` 盘点的全部达标官方长篇，每部取首个入口，全部存储操作在内存 SQLite。节点正文使用已发布入口文本作为存储夹具，显式校验保持原位置的状态补丁；这不代表生成了三轮合格新剧情。

已验证：超过两条的承接移出窗口但仍留在存储；切换兄弟分支不带入另一路 lineage；重复 request 被数据库唯一约束拒绝且重建上下文哈希不变；candidate/unknown/rejected 不进入写作；confirmed 仍要求当前分支与可追溯来源；连续性摘要不能提升为 confirmed 事实；外部对象变更不改写快照，rejected 不可复活。

这是存储与 Builder 的边界回归，不等同于 API 幂等恢复、自动记忆提炼或生产写入验收。`_continuity_window` 仍信任调用方提供的已提交 lineage，不能接收未经筛选的草稿列表。
