状态：完成记忆迁移不变性修复、运行时失效原因审计，以及物品长链选择的离线配对测量。正式语义纠错/撤销入口、通用候选注册表和真实正文验收仍未完成。

## 审查发现与修复

1. 原 `validate_dynamic_memory_transition` 在确认继承关系后直接返回，未禁止同时改写 `content`、`sourceIds`、可见性等字段。已有运行路径复制原快照，未发现因此产生的错误正文，但其他调用方式可以绕过“不改写事实”的设计。本轮将继承可变字段限定为新身份、目标分支、序号和继承关系；同一记忆的状态迁移仅允许改变状态、有效性、序号和冲突引用。
2. 已继承记忆保留 `parentMemoryId`，原守卫会把它的后续拒绝迁移误当成再次继承，导致无法保留继承关系进行拒绝。本轮区分新身份的跨分支继承与同一身份的状态迁移；拒绝时保留原内容、来源及继承链，拒绝记录仍不能复活。
3. 原选择器仅给出 `state_changed` 总数，无法区分新证据替代与缺少当前可用凭据。本轮新增有界 `memorySelection.lifecycle` 审计，提供原因、原记忆 ID、原始/当前分支，以及确有对应记录时的新记忆 ID。不会复制旧正文。
4. 对异常类型的原正文/审核结构，选择器按损坏来源省略，不提升旧记录，也不因为这类来源形状损坏中断全部记忆选择。
5. 最后复审发现 Python 相等比较会把 `true` 与 `1` 视为相等；改为规范 JSON 表示比较，保留结构化事实中的类型差异。补充测试确认状态迁移不能借此改写事实。

新增审计只附在既有上下文装配诊断上，不属于 `ContextBundle` 的提示内容。`chapter`、`repair`、`result_contract`、`fact_extract` 和 `grounding_review` 都不接收生命周期明细。新预生成规则为 `/22`，防止待提交草稿跨越此次校验规则升级；已存凭据仍是 v1/v2，未改写旧会话。

## 冲突与撤销的决策边界

| 情况 | 本轮行为 | 权威状态/历史处理 |
| --- | --- | --- |
| 同一实体被后续已确认状态替代 | `superseded`；引用实际通过复核且符合当前状态的新记忆 ID | 不再选旧记录，原历史不改；不把历史事实判为虚假 |
| 当前状态不同，但没有对应的可用新记忆 | `state_unverified`；省略旧记录，不补造替代内容 | 仅表示记忆证据链未闭合，不表示既有权威状态失去效力 |
| 原正文、审核、包或凭据损坏 | `source_invalid`；不信任该来源 | 不改写来源，不据此恢复其他旧状态 |
| 与当前行动无关或预算不足 | 仍是 `irrelevant` / `selection_budget` | 不撤销、不拒绝，不产生失效迁移 |
| 明确失踪者重现、伤者恢复、物品转交 | 必须先经过已有后果契约和完整提交检查，再进行记忆选择 | 记忆层无权决定实际状态变化 |
| 永久死亡、永久离队或永久毁坏的反向操作 | 继续由原权威规则拒绝 | 不新增复活、修复原物或追溯撤销通道 |
| 已结束目标/问题重新开启 | 继续拒绝重置；按现有规则新建独立目标/问题 | 保留结束记录与原始身份 |
| 自由文本称“此前事实错误” | 不自动执行撤销或转为确认事实 | 正式更正需要独立业务契约；本轮不提供此入口 |

`superseded` 是选择审计结果，不是把存储中的 `confirmed` 改成 `rejected`。真正的语义拒绝需要可信冲突来源；纯迁移守卫仅校验结构和不变性，不证明 `conflictWith` 引用存在或语义成立。不能将本轮修复描述为通用拒绝/撤销持久化管理器。

生命周期审计最多记录 32 条明细，余项只累加 `omittedDetails`；计数保持完整。`source_invalid` 按原因分支计数，其他两类按原记忆记录计数。替代依据与是否最终装入提示无关：新事实即使因场景无关或预算未选中，也可以证明旧事实已被替代。

## 长链测量与结果

测量脚本：[dynamic_memory_benchmark.py](../test_support/dynamic_memory_benchmark.py)。枚举所有达标官方长篇，当前为《太虚遗录》`0.1.3`，母本 102610 汉字。构造 32、128、512 回合的物品状态链，各回合正文使用母本中不同的原始段落；不用重复模板补足长度。

**状态与审核记录是成本测量用的合成夹具，原著段落与合成转交没有真实剧情因果关系，绝不能用作后果正确性或正文质量证据。** 不提交游玩会话，不调用模型，不测数据库加载、完整上下文装配或前端。

每档重复 7 次，P95 采用最近秩；样本较少，仅是本机观察值，不设为通用性能门槛。配对输入已固定身份和时间，且逐档核对输入哈希、选中来源完全一致。选择器在单次调用内复用实体当前状态索引与哈希，不使用跨请求缓存，避免跳过来源漂移复核。

| 回合数 | 修改前中位/P95 ms | 修改后中位/P95 ms | 注入 | 修改后审计明细/省略明细 |
| --- | --- | --- | --- | --- |
| 32 | 2.664 / 2.815 | 2.972 / 3.022 | 1 条 / 11 字符 | 20 / 0 |
| 128 | 10.346 / 10.433 | 11.320 / 11.625 | 1 条 / 11 字符 | 32 / 84 |
| 512 | 40.113 / 41.606 | 44.390 / 44.691 | 1 条 / 11 字符 | 32 / 468 |

结果说明：诊断没有随历史长度增加模型注入，当前物品负载中选择成本近似随链长增长；最终严格类型校验版本在 512 回合的中位耗时比基线多约 4.3 ms，不能宣称提速。尚未测目标/剧情线大量累积、数据库反序列化成本或真实行动检索召回率。

原始数据保留于[固定输入基线](evidence/context-management-2026-09-22/memory-selection-baseline-2026-09-27.json)和[最终独立测量](evidence/context-management-2026-09-22/memory-selection-lifecycle-isolated-2026-09-27.json)，包含各次耗时、源文件哈希、输入哈希和期望/实际来源。最终测量在本轮回归进程全部退出后运行；`memory-selection-lifecycle-2026-09-27.json` 是严格类型比较前的中间版本，`memory-selection-lifecycle-final-2026-09-27.json` 测量时回归仍在运行，均保留但不用于上表。更早的 `memory-selection-before-2026-09-27.json` 是未固定身份和时间的预跑，不用于配对结论。
