## 实现范围

- 原有结果规划调用同时输出 `scenePlan`：起点、过程、结果、停止点、建议汉字区间与原因，以及人物知识和观察限制。不为计划新增一次调用。
- `targetCjk` 根据实际交流、信息辨析、冲突与情绪变化选择；不再按步骤数、转场与否机械分档。50～2000 是计划字段的保护范围，不是普通场景默认长度。
- 完整执行要求优先于字数。正文短于建议区间不会触发扩写、重试或拒绝；真正遗漏行动、越权或事实错误仍须修复。正文原有 3500 非空白字符上限保留，汉字统计使用 `[\u3400-\u4dbf\u4e00-\u9fff]`。
- 场景计划在写正文前验证步骤覆盖、人物编号与引文存在性。计划不能增加授权步骤，也不是事实来源；引文存在并不证明语义支持。
- 区分事实、转述、推断与未知。公开证据仍只包含开场已知信息与当前路线近期正文；不把内部位置、状态或隐藏信息加入公开证据。
- 独立复核不接收规划器拟定的回答或第一轮审查结论。它读取玩家原话、公开前情和观察限制；`boundaryChecks` 必须逐项覆盖观察限制，遗漏、重复或语义拒绝都不能直接通过。
- 统一问题清单继续覆盖行动、背景、连续性、状态。有效的错误短引文只遮蔽对应句子；无效引文仍以完整段落保守拒绝。同段同类的另一处错误不会被去重吞掉。
- 局部修复允许自然缩短，继续检查重复、残留标记、对白引用依赖，并重新执行完整复核。记录修复前后正文、问题类型、结果及失败原因。原有失败正文保留策略继续生效，但保留正文属于未确认草稿。

主流程不再调用 `expand_scene_paragraphs` 或 `reader.scene_expand`；旧辅助函数及其离线测试暂留兼容。本轮没有进入完整 P4、自动配图或手机端开发。

## 尚未解决的关键问题

1. **角色知识仍缺少可靠的获取路径。** 开场事实对玩家公开，不代表所有 NPC 都已知。最终告知中的 NPC 使用了金屑位于刻痕泥中的信息，但其获知路径尚未被本轮证明；`scenePlan.knowledge` 只是写作安排，不能替代权威知识账本。
2. **语义支持检查仍会错把同主题当证据。** 前两批把“刮出”视为支持“用针尖挑出”，把试炼背景视为支持发放时间。引用存在性校验只能防伪造引用，不能独立证明主体、工具、时间和条件受到支持。
3. **局部修复可能只改变语气。** “可能”“或许”不能修复一个无来源的物性前提。现有完整复核会继续审查，但受模型漏检和传输故障影响，尚未稳定。
4. **复杂场景的篇幅适配尚无真实验收。** 本轮三个输入都是限制明确的短交互，较短正文合理；这不证明复杂交锋、多人冲突能按需充分展开。
5. **三类连续通过未完成。** 最终批次询问失败，等待的父节点是告知。没有三连质量通过证据，也没有桌面端连续试玩通过证据。

下一轮仍应集中于 P0/P1：角色知识的获取依据、断言与来源的细粒度支持、同义错误修复，以及复杂场景与三类连续回放。暂不以扩大审查轮数、提高固定字数或自动扩写代替这些修复。
