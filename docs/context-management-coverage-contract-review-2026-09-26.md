## 覆盖契约

[实现](../test_support/context_qualifier_coverage.py)复用冻结的原文单元、片段和实体出现引用。每个单元中，每个无歧义的登记人物出现位置生成一个待判断项，列出该单元内可选择的无歧义边界引用。多人物分别判断；不枚举人物与所有边界的笛卡尔积，不根据实体共现推断位置事实。

任务 ID 绑定原文与引用表。模型返回独立的 qualifier-coverage/0.1 协议，每项含 slotId、disposition、items：

| disposition | 必需内容 | 程序能确认的范围 |
| --- | --- | --- |
| position | 至少一个原位置协议的候选；主体属于该任务、边界属于其引用列表，core 位于该原文单元 | 候选引用和格式有效；不能证明位置或限定判断正确 |
| non_position | items=[] | 模型明确声称这里没有位置；该声称仍未验证 |
| unresolved | items=[] | 该项明确未决，继续展示给后续审核 |

全部待判断项必须恰好回答一次。未知、重复、其他原文的 ID、遗漏决策、错主体/边界、空 position、非位置夹带候选和跨单元 core 均拒绝。旧数组不自动升级；有待判断项时，顶层空数组不能表示完成。符合引用与范围约束的候选仍交给冻结的原解码器检查，条件前提可以保留在独立单元中，不被改写或搬移。

decisionsComplete=true 只表示任务台账填写完整。semanticCoverage 始终为 unverified，reviewRequired=true、productionEnablement=false。模型把真实位置答成 non_position 仍可能满足结构契约；测试明确保留这个反例，并由原冻结金标评分认定其语义不匹配。

## 未覆盖范围与预算

- 单元没有无歧义的登记人物、没有可用边界或存在歧义引用时，原因留在本地 pendingUnits。条件前提和普通动作单元也可能出现在这里；它不是“漏掉了事实”的结论。
- 代词、未登记称呼、跨单元关系没有被自动消解。同一单元同时包含已登记人物和其他未登记主体时，也不能凭一个任务回答宣称整句覆盖；同一个人物的多条关系仍可能漏提。
- 即使所有单元都有任务且全部回答，也不证明完整语义召回。当前只约束 same_unit_registered_occurrences，不把索引范围当正文的全部事实范围。
- 每篇最多 64 个单元、32 个待判断项、每单元 8 个边界引用；本地索引最多 16,384 字符，响应最多 64 个位置候选。同时保留既有 12,000 字符原文、128 片段及 256 实体出现上限。超预算直接拒绝，不截断，不增加模型调用来绕过限制。这些是实验预算，不代表已适配整章生产正文。

## 精简模型输入

最初完整索引包含 schemaVersion、范围、单元 ID、任务引用和未决原因。离线测量发现它让 user 输入增大 67.55%，不能直接把全部本地诊断数据注入模型。

[精简投影](../test_support/context_qualifier_coverage_projection.py)只发送原 source、原 entityRefs 和 coverageTasks。每个任务只提供任务 ID、subjectRef、boundaryRefs；单元 ID 已能由实体引用对应的片段确定。范围说明、未决原因和验证台账留在程序端，解码仍重建完整索引校验，不因投影而放宽预算或丢弃未决单元。没有复制第二份正文、额外来源、历史审核或权威状态。

| 30 条样例的 user 输入装配 | 字符数 |
| --- | ---: |
| 原输入 | 13,383 |
| 包含完整索引 | 22,423 |
| 精简任务投影 | 17,126 |

精简版比完整索引减少 5,297 字符（23.62%），仍比原输入增加 3,743 字符（27.97%）。这是 JSON 字符装配测量，不包含尚待冻结的新 system 提示，不是实际 token、时延或准确率收益。只有后续证明覆盖收益值得新增成本，才考虑继续采用。
