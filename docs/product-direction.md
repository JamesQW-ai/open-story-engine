# 产品方向与演进边界

## 产品定位

`open-story-engine` 的长期目标不是把原著改造成固定选项式游戏，而是让读者以自己感兴趣、且具有适当使用边界的小说为基础，构建更具互动性、可读性和连续因果的私有同人叙事体验。

原著提供世界观、人物、已发生事件和可选的规范剧情方向；用户通过自由文本参与故事，并可在受控的规则与状态边界内改变角色选择、关系和后续发展。当前“私有娱乐、不向外发布”是产品使用场景，不构成对外部作品的授权或使用权判断；外部来源、传输给模型服务和发布行为需要在未来单独设置来源与权限边界。

## 两种故事模式

### `canonical_play`

原著规范主线是默认体验。

- 从固定的 `StoryPackage`、默认起点和规范 `StoryDirection` 创建会话。
- 原著的不可变世界事实、已发生事件和规范结局条件保持有效。
- 玩家可以自由表达当前行动；规则结果可以引入代价、失败和有限偏离，但故事优先沿原著主线汇聚。
- 当前 CLI MVP 只实现此模式，用《雨夜候车室》验证完整闭环。

### `derivative_co_creation`

未来允许用户以原著为素材创建一条新的私有连续性，而非被迫回归原著主线。

- 用户可从指定的原著 `entryNodeId` 开始，或选择只继承世界观与部分人物设定。
- 用户可代入一个原著角色，或建立一个新角色（original character）。
- 在选择新的高层剧情方向后，后续故事可以完全偏离原著；原著仅作为经确认的世界、人物与历史材料来源。
- 该模式产出新的会话连续性，不回写或修改原著 `StoryPackage`。

## 未来会话契约

`StoryPackage` 继续作为不可变、版本化的原著内容。进入 `derivative_co_creation` 时，系统应创建独立的 `SessionStoryContract`，而不是直接改写故事包。

```text
StoryPackage（原著固定内容）
  + 选定起点 / 继承范围 / 玩家角色
  -> SessionStoryContract（本局故事契约）
  -> GameState + game_events（本局运行期数据）
```

该契约至少需要记录：

- `sourcePackageRef`：原著包 ID、版本与来源引用。
- `entryNodeId`：用户从哪一个原著节点进入；只继承世界观时可为空。
- `continuityScope`：`world_only`、`world_and_characters` 或 `canonical_until_entry`。
- `persona`：玩家角色类型、背景、动机、能力、初始关系、初始知识边界与可见实体。
- `immutableFactRefs`：本局仍不可改写的世界规则与已确认事实。
- `direction`：用户确认的高层剧情方向，不是具体行动菜单。
- `provenance`：用户新建设定、系统推导结果和原著事实之间的来源关系。

当用户代入原著角色时，`persona.sourceCharacterId` 指向对应角色，且该角色不应同时作为独立 NPC 再次行动。当用户创建新角色时，其能力、关系、知识和初始资源必须显式定义；叙事器不能仅因其“来自原著世界”而补写未确认的人际关系或能力。

## 原著主线与分叉的表示

原著正文应先被标注为一条可阅读的规范时间线。故事包中则使用带条件的有向无环图（DAG）表示节点转移：实线是规范原著路径，条件边是可达的偏离、代价或重新汇合路径。

不要为每一句玩家输入创建新的故事节点。节点表示可审阅的剧情锚点；玩家的自由行动先由 `RuleEngine` 转为状态变化，再由状态和转移条件决定是否抵达、偏离或重新汇入某个节点。

## 演进顺序

1. 完成标准小说母本到 `canonical_play` 故事包的手工标注与可复现推演。
2. 设计 `SessionStoryContract` schema 和来源追溯规则，但不改变既有存档模型。
3. 支持从原著节点进入，以及代入原著角色的会话创建。
4. 支持新角色设定、继承范围选择和偏离原著主线的私有连续性。
5. 在规则边界稳定后，再评估更开放的共创与内容导入能力。

在第 1 步通过前，不实现角色创建器、节点选择器、开放式世界分支或自动小说导入。
