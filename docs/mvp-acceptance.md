# MVP 验收标准

## 当前产品验收：方向 2（最高优先级 MVP）

2026-09-10 起，当前 MVP 面向完整或不完整读过原著的用户，验证“选择剧情节点与介入角色 -> 改写剧情 -> 持续阅读与继续分支”。三个方向及优先级以 [产品方向与演进边界](product-direction.md) 为准。

用户指出此前存在“主要实现方向 2、实际验收方向 1”的错位。本标准据此调整验收对象：方向 1 的图片吸引、新读者从零引导和“全程选 1”读原著，以及方向 3 的从零创作均不作为方向 2 的完成门槛。方向 2 仍须提供足够的入口背景和可读、连贯的正文，不能以用户读过原著为由省略。

### 范围与必过场景

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 已读与部分已读用户开局 | 分别以完整读过和只读到所选节点的用户视角选择原著、角色与可进入节点 | 可理解角色、当前处境和所继承前史，不需要先从头读完整本；开局契约固定包版本、节点、角色与知识边界。 |
| 角色介入 | 使用一个原著角色开局，检查入口及后续叙事 | 玩家身份与状态一致，不同时生成一个独立行动的同名 NPC；读者知道的后续情节不会自动成为角色知识。新建角色若纳入交付，应另覆盖其设定与知识边界。 |
| 主动改写 | 选择一条偏离原著的方向，并覆盖自由文本输入 | 结果体现用户意图与规则允许的后果，形成可追溯分支，不强制回到原著；不支持的输入有明确说明且不误提交。 |
| 持续共创 | 在同一偏离分支至少完成三个连续回合 | 正文承接已确认行动、人物关系、状态和未解事项；方向选择有实际后果，后续选项可继续推进。已偏离的祖先链不因选择相似目标而拼回原著段落。 |
| 分叉与续玩 | 从同一父节点形成两个分支，退出后重新读取并继续其中一个 | 父节点历史不被覆盖，分支互不污染，角色、方向、正文与状态可正确恢复并继续。 |
| 来源与状态边界 | 对比原著包、会话契约、已确认状态和生成正文 | 原著包保持不变；生成内容不将未确认事实或能力当作既成事实；状态变更经本地规则校验并可追溯。 |
| 失败恢复 | 注入模型超时、无效输出或事实冲突后重试 | 未采纳草稿不写为正式剧情，不损坏分支；错误可识别，同一逻辑请求不重复提交。 |

### 完成门槛与证据

1. 上述场景均有对应证据，注明故事包 ID/版本、入口、角色、输入步骤、会话/分支引用、预期与实际结果。
2. 确定性回归覆盖契约、状态、分支隔离、持久化和失败路径；保留下文早期 CLI 基础回归的适用检查。
3. 使用真实模型完成主动改写与至少三个连续回合的正文验证；`mock` 只证明结构和规则，不证明共创正文体验。真实模型专项运行遵循 [真实 LLM 评估 v0.1](live-llm-evaluation-v0.1.md)，既有专项结果不能自动替代本表的产品场景证据。
4. 人工试玩同时覆盖完整读过和不完整读过原著的视角，检查入口可理解性、角色代入、改写后果和持续可读性。每项判断附具体回合及问题，不能只写“文笔不错”。
5. 记录实际验收入口（CLI/API/玩家端）及其能力边界；底层接口通过不能自动视为玩家端流程通过。

当前状态：方向 2 正在实现；本次只对齐产品方向与验收标准，未运行上述产品验收，结果为 `Unknown`（未验证）。历史通过结果保留其原有范围，不自动升级为方向 2 MVP 通过。

## 早期 CLI 基础回归（历史范围）

以下保留首个固定故事切片的技术验收标准。“范围”“完成门槛”和真实 LLM 附加检查仅指这一历史切片，不排除当前方向 2 的共创能力，也不替代上面的产品验收。

### 验收对象

本标准只适用于 `rainy-waiting-room` 的单机 CLI MVP。验收目标不是证明模型文笔，而是证明互动叙事引擎能让一个预置故事包稳定地完成一局可追溯的游戏。

### 范围

必须交付：

- 加载并校验一个 `StoryPackage v0.1`。
- 创建、读取和继续一个本地游戏会话。
- 接收自然语言玩家输入，并归类为 `investigate`、`negotiate` 或 `risk`。
- 由代码执行前置条件、随机检定、状态变化和节点转移。
- 记录不可变事件与可验证的当前状态快照。
- 使用 `mock` 叙事器完整试玩；真实 LLM 适配器作为受控的附加验证。
- 通过 `status` 查看对玩家有意义的当前目标、地点、背包、关系与已知事实。

不在范围内：图形界面、任意小说解析、图片、用户账号、联网同步、多人故事、共创模式和自动生成故事包。

### 必过场景

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 内容校验 | 加载合法包与缺少引用的非法包 | 合法包可启动；非法包在建档前被拒绝并指出引用错误。 |
| 新建会话 | 以默认方向启动《雨夜候车室》 | 初始状态与故事包模板一致，首个事件和会话 ID 可查询。 |
| 调查 | 在候车厅寻找线索 | 仅在规则允许时取得线索或物品；状态差异写入一个事件。 |
| 交涉 | 与姜序或陈砚交流 | 关系、通行资格或压力变化由检定决定，不由叙事文本决定。 |
| 冒险 | 尝试绕过封锁或进入隧道 | 未满足前置条件时拒绝状态变更；满足条件后执行确定的风险结果。 |
| 非法输入 | 空输入、无法解析输入或不可达行动 | 不写入新的游戏状态；向玩家返回可继续操作的说明。 |
| 状态重建 | 从事件序列重放会话 | 得到与当前快照完全相同的版本化状态。 |
| 结局 | 覆盖三个已定义结局条件 | 每个结局只由可持久化状态触发，且终局后不再接受普通行动。 |
| 叙事隔离 | 使用不同 `Narrator` 实现重放同一已判定回合 | 检定结果、状态差异和节点转移不变；仅正文可不同。 |

### 不变量

- 一次已提交事件只能追加，不能被后续回合修改。
- 所有运行期实体引用均使用稳定 ID，不能通过显示名称匹配。
- 每次状态写入必须伴随对应的事件记录，并处于同一 SQLite 事务中。
- `RuleEngine` 是唯一允许产生 `StateDelta` 的模块。
- LLM 结构化输出未通过 schema 校验时，不得推进回合。
- 默认随机源必须可注入并支持固定 seed，以便测试和问题复现。
- 任一非终局状态至少存在一个可行的规则路径；模型不得靠自由收尾掩盖死路。

### 完成门槛

满足以下全部条件才可进入真实 LLM 调优或 Web 界面开发：

1. 自动化测试覆盖上述必过场景，且本地全部通过。
2. 使用 `mock` 叙事器可以从新建会话走到三个结局。
3. 从任意测试检查点重放事件可重建相同状态。
4. 人工试玩至少完成一条成功路径和一条受控失败路径；两者都能继续阅读、理解当前目标或明确结束。
5. `status` 输出与数据库中的快照和最后事件一致。
6. 不依赖 LLM 也能验证故事包和执行全部规则。

### 真实 LLM 附加检查

真实 LLM 不改变上述完成门槛。启用后还必须验证：

- 解析器输出只使用约定的行动类型、实体 ID 和字段。
- 叙事器不声称尚未发生的状态变化，不替玩家补写行动意图。
- 单回合调用次数、输入上下文和输出长度均受配置上限控制。
- 模型调用失败时，已提交的规则结果仍可用可恢复标记重新叙事，而不会损坏存档。
