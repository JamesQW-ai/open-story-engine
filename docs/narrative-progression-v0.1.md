# 连贯叙事推进 v0.1

## 目的

本契约解决“规则已经推进，但读起来像重复模板”的问题。它不把玩家输入编译成固定选项，也不让叙事器自由决定剧情；它在规则确认状态之后，从故事包的 `narrativeGraph` 选择下一个可达叙事锚点。

```text
上一叙事锚点与未解决线索
  + 本回合已确认状态
  -> narrativeGraph 的条件边
  -> 下一叙事锚点
  -> 仅输出新的承接段落
```

## `narrativeGraph`

每个故事包的 `story.narrativeGraph` 包含：

- `startBeatId`：新会话尚未发生任何运行期事件时的叙事锚点。
- `beats`：可审阅的剧情锚点。每个锚点绑定规则节点，并声明短摘要、可写入正文的场景锚点和未解决线索。
- `edges`：从一个锚点到另一个锚点的有条件边。它有稳定 ID、条件、是否属于原著规范路径，以及本次转移专属的承接文本。
- `endingBeatIds`：每个可达结局到结局锚点的映射。结局优先于普通边，保证终局不会被错误地续写为普通场景。

`StoryDirection` 仍是会话级高层目标，`ActionIntent` 仍是当前尝试；`narrativeGraph` 只回答“规则结果意味着此刻进入哪一段连续剧情”。它不直接向玩家暴露规则行动菜单；面向玩家的高层选择由锚点的 `nextDirections` 单独提供。

每个 `beat` 还可声明 `nextDirections`。它们是面向玩家的高层剧情分支，包含标题、简述、可达条件和 CLI 试玩用的 `suggestedInput`：

- 标题与简述展示为“可能的剧情方向”，例如“先取得证据”或“救援优先”。
- 条件不满足的方向不会展示。
- `suggestedInput` 只用于编号选择时转换为内部行动；它不是展示给玩家的具体行动菜单。
- 玩家始终可以绕过编号，直接输入自定义方向或行动。当前 mock 解析器只接受可映射到既有规则的输入；开放方向的合理性校验属于后续阶段。

## 分叉与汇合

规范原著路径可以写为 `A -> B -> C -> D -> E`。受控偏离可写为 `A -> F -> H -> D -> G`：

- `F`、`H` 是有独立条件和后果的叙事锚点，不是用旧段落替换几个词。
- 汇合到 `D` 时，`D` 的摘要和开放线索必须能承接两条已确认前史；若不能，应创建不同的汇合锚点。
- `G` 必须在故事包中被标注为非规范结局，不得以“原著后续”称呼。

《雨夜候车室》当前保留规范的“证据优先后救援”路径，也支持“先请姜序下隧道、未取得证据即救援”的受控偏离。后一条会进入 `ending_rescue_without_proof`，而不是被强行拉回原著规范结局。

## 运行期连续性

`event_narrations` 对每个已提交规则事件保存正文和 `continuity_json`：

- 当前 `beatId`；
- 该锚点的摘要与未解决线索；
- 当前规则节点与地点。

下一回合读取最近一条叙事连续性，以它为图遍历起点。正文不拼接所有历史段落，也不重放开场；它只使用承接边、当前锚点和本回合已确认的状态效果来写下一段。成功剧情正文不追加固定的“推进成功”“未解线索”提示语；下一步可能性由正文后的 `nextDirections` 单独呈现。历史文本仍可按事件序列回顾。

叙事写入失败时，规则事件不回滚。下一次叙事生成从最近成功保存的连续性继续，且不得重新检定。

## mock 与 LLM 边界

当前 `MockNarrator` 直接采用故事包中的承接文本和锚点文本，用于验证图遍历及连续性存储。未来 LLM 适配器可以扩写这些受控输入，但只能：

- 描述已确认的状态、实体与结果；
- 保持当前锚点的视角、场景与未解决线索；
- 产出当前回合的一段新文本。

LLM 不得创建边、选择未满足条件的锚点、改变 `continuity_json` 中的事实，或替玩家补写未输入的行动。
