## 本轮改动

- `api_narrative.py` 与 `reader/narrative.md`：写作入口以用户原话为准，将已经结束的前情明确隔开；末尾再次给出当前动作与原写作预算，避免从上一页开头重新演出。重写仍保留普通场景预算，不因修错直接改成摘要。
- 局部修复新增两个无模型调用的检查：若修订段新复制了相邻段连续至少 15 个汉字的片段，拒绝该修复；若删掉前文台词却保留后文明确引用，要求同步衔接。前者忽略标点进行比较，只拦修复新增的重复；后者只检查可逐字证明的既有对白依赖，不宣称覆盖所有指代或因果关系。
- 修复输入附各段原汉字数和对白依赖。普通场景尽量保留有效内容，禁止以相邻台词填空；连带修改仍受最多 8 段、原文一半的原有范围限制，不为通过修复扩大预算。
- 综合复审和独立背景复审收到 `priorRepairIssues`，核对语义是否实质修复；不携带旧版完整正文，不要求模型无条件沿用旧判定。
- 补写收到公开来源，明确限制包裹内部观察、地点规模等新增事实；减少逐句引用原对白再解释其语气的机械扩写。独立核对的合法当场反应说明要求简短，但保留全量逐句覆盖和来源检查。
- 在第二批真实测试暴露问题后，又把补写的确定性重复检查提前到候选合并阶段。重复补写直接丢弃，原稿在同一轮接受完整审查，避免白占一个正文修订回合。此最后代码改动已做离线集成验证，没有混入前面的真实批次结果。

本轮只修改读者叙事流程、对应提示词、两份 API 测试和本报告证据。没有变更主数据库、母本、模型配置、前端或配图。既有未提交改动保留。

## 真实模型测试口径

使用配置中的 `deepseek-v4-pro:cloud`，每批从同一正式父分支的数据库只读备份开始，调用 `PlayService.continue_turn`，成功后接续最新分支，失败不推进。每回合仍限制最多 18 次底层调用、最多三轮正文，不加预算求一次成功。没有浏览器连续试玩，也没有生图。

汉字按 `[\u3400-\u4dbf\u4e00-\u9fff]` 统计。首片段是服务层首次正文回调；完成耗时包括审查、修复和提交，不等于纯生成时间。tokens 为供应商报告的全部输入输出。失败回合不使用零汉字掩盖保留稿，保留稿单列且未确认。
