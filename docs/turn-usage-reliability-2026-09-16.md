## 交付结果

本轮修复失败重试的耗时与 token 统计，不改变生成策略、不增加模型调用或审查轮次。

- 同一草稿重试时，前次统计随 `previous_attempts` 保留，新尝试单独计量；缓存命中不新增生成尝试或调用。
- 失败调用返回有效 usage 时，保留已报告 token；存在失败链路或缺失回执时，总量仍为 `null`。
- 成功和失败任务的完成状态、统计及持久化在同一把锁内完成，避免前台先看到结束、重试却读不到统计。
- 正文完成后的方向生成、校验或取消异常，同样携带已产生的用量和审计。
- 已返回正文产物被取消时，只保留用量和审计，不形成可提交草稿。旧任务在重试后才返回的回执补入对应历史尝试，不能覆盖新任务；旧选中者释放也不能覆盖新任务落盘结果。

## 统计契约

`TurnDrafts.view()` 返回的 `metrics` 保留当前尝试指标，并新增 `cumulative`。累计值由当前指标与保留的历史尝试重新计算，不递归存储累计结果。

| 字段 | 含义 |
| --- | --- |
| `attempts` | 当前尝试及保留历史的数量，缓存读取不增加 |
| `calls` | 已计量尝试中的网关调用次数，不是底层 HTTP 重试次数 |
| `reported_tokens` | 供应商回执中已知的 token 总和；有缺口时只是下界 |
| `unreported_calls` | 已计量调用中回执缺失或链路不完整的调用数 |
| `unmeasured_attempts` | 尚未结束或旧记录缺少有效用量字段的尝试数 |
| `tokens` | 仅在每次尝试均有完整统计且没有缺失调用时给出；否则为 `null` |
| `queue_ms` | 各次尝试排队时间之和；任一次缺少计量则为 `null` |
| `complete_ms` | 各次工作线程执行耗时之和；任一次缺少计量则为 `null` |

`complete_ms` 包括该次生成与校验，不包含排队、玩家两次尝试之间的停留时间或正式提交耗时，也不是“首字／完整正文／方向可用”三个前端体验指标。取消任务可先显示 `expired`，供应商仍在返回时统计保持未知；回执到达后补齐。进程中断后无法找回的用量不能补造。

单次流式响应的 usage 是累计回执，取最后一个有效值一次，不逐事件相加。只接受非负整数；布尔值、负数、字符串和缺失值均不能作为 token 总量。明确记录零次调用的模拟生成可显示 `tokens: 0`；没有记录不等于零。

以上是网关回执与本地耗时统计，不是实际账单或金额核算。供应商未报告的底层重试成本仍未知。规则版本保持 `/18`，因为没有改变可提交正文或权威状态规则。
