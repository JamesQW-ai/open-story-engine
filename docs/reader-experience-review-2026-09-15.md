状态：已记录、已核对实现，待开发。本文不代表功能修复或真实模型验收通过。

## 范围与结论

记录 2026-09-15 用户桌面试玩反馈。依据当前代码、官方角色开局配置和两个已有会话的只读 HTTP 数据分析；本轮不修改业务代码、提示词、故事包、图片或存档，不发起模型生成。没有重新进行浏览器操作，视觉现象采用用户反馈，结合代码解释原因。

产品范围继续采用：官方长篇、未知原著的玩家、选择角色后直接进入对应开局、预设方向提前生成、自定义方向提交后生成、不开放小说上传、仅桌面端。旧的“已读原著后选节点”说明不适用。

核心问题是一次选择是否带来完整、可感知且被保存的剧情变化。增加正文长度、方向数量或图片数量，都不能单独保证体验。

| 编号 | 问题及核查结果 | 后续目标 | 优先级 |
| --- | --- | --- | --- |
| R1 | 篇幅无最低要求，样本长短不一；尚无读者体验数据证明足够 | 按行动复杂度组织完整场景，建立篇幅与等待时间联合基线 | 高 |
| R2 | 流式期间不读取插图，完成后把图插到段落前 | 固定开局图文顺序，不让晚到图片推移已读文字 | 高 |
| R3 | 开局仍有“选择下一步行动”按钮，点击才进入会话阅读页 | 当前正文下直接显示方向及自由输入，取消中间操作 | 高 |
| R4 | 可见方向被限制并补齐到两项，存在通用兜底文案 | 数量由当前真实抉择决定，内容由分支状态推导 | 高 |
| R5 | 已有行动回应校验允许“尝试后受阻”，不能证明明确结果得到兑现 | 区分行动尝试与指定结果，重大结果同时进入正文和状态 | 最高 |
| R6 | 太虚角色目标统一为通用文案；当前任务可能直接取第一条选项 | 角色目标、当前目标与玩家新目标分开维护并随剧情更新 | 高 |
| R7 | 人物图使用圆点与姓氏，未消费已有肖像 | 已有角色图作头像；小角色使用稳定的预设头像，保留详情交互 | 中 |
| R8 | 图谱没有展示死亡、永久离队等状态；当前淡化只表示焦点关系 | 使用当前分支中玩家已知的状态，灰度与明确状态标签配合 | 高，依赖 R5 |

## R1：正文长度与场景完成度

### 实际样本

计数口径：汉字数按 `U+4E00–U+9FFF` 统计，非空白字符另列，二者不等于 token。读取接口为 `GET /api/v1/sessions/{sid}/branches` 及对应分支详情，没有提交新回合。

| 会话 | sequence | 类型 | 汉字数 | 非空白字符 |
| --- | --- | --- | ---: | ---: |
| 当前试玩 `9a9a4bf9-514e-50c5-93fc-1584a4cf495d` | 0 | 陆照临开局 | 266 | 298 |
| 既有 P1 样本 `16e4415f-5f12-51c5-b2d9-e2fc8c8cdb88` | 0 | 开局 | 224 | 249 |
| 同上 | 1 | 后续分支 | 934 | 1101 |
| 同上 | 2 | 后续分支 | 571 | 654 |
| 同上 | 3 | 从开局改选的另一分支 | 582 | 670 |
| 同上 | 4 | sequence 2 的后续分支 | 441 | 504 |

当前会话只有开局，不能据此断言“每回合只有两三百字”。另一个会话的四段后续正文为 441–934 个汉字，中位数 576.5；其中包含同父分支的不同选择，不是连续四回合。样本少且同属陆照临路线，不代表所有角色或长篇全过程。

当前提示词明确“不设最低字数”，上限为 3500 个非空白字符；固定开局另有约 400–700 字的软建议，但不是硬验收条件。当前开局交代了父亲失踪、山门、伤者和关门危机，具备基本切入信息；篇幅本身不足以证明体验好或坏。

抽读已有后续正文发现，检查伤势、隔门询问、保护文书等行动可以得到具体描写，但相邻片段仍停留在山门外等候。是否合理取决于玩家所选行动；仅延长雨景、疼痛和等待的描写，并不能增加剧情推进感。

### 建议节奏，待试玩验证

| 场景类型 | 建议汉字范围 | 完成条件 |
| --- | --- | --- |
| 初始场景 | 400–700 | 让未知原著的玩家明白身份、必要关系、眼前危机和可行动之处 |
| 普通剧情推进 | 600–1200 | 玩家行动得到处理，人物或局势发生有依据的变化，形成下一抉择 |
| 重大行动、冲突、反转 | 1000–1800 | 写清实施过程、阻力、明确结果及即时影响 |
| 简单询问或短暂过渡 | 200–500 | 问题有回答或行动有结果，不为了达到字数反复描写 |

这些是试验目标，不是用户已经确认的硬指标，也不是已验证的行业标准。先看场景完整性，再看篇幅：行动 → 外界回应或阻碍 → 处理过程 → 明确后果 → 新决策。允许短场景，但不能每做一个小动作就逼玩家再点一次；允许长场景，但不能替玩家连续作出未授权的重大决定。

十万字是母本体量，不意味着每次选择必须输出一整章，也不意味着每条玩家路线必须写满十万字。后续同时测量首字延迟、完整正文耗时、预生成命中、阅读完成情况、推进感与重复描写；不以无条件加字换取表面“长篇感”。

## R2–R3：开局图文顺序与方向入口

### 已核实原因

- `PackageDetailPage.tsx` 在开局页接收流式正文；结束后才取得正式 session/branch，并切换 `StoryProse` 的 key。
- `StoryProse.tsx` 在 `streaming` 时跳过插图请求；流式结束后读取素材，将图片放在对应段落之前。即便使用预制图片，也可能出现“先读文字，再在文字上方插图”。
- 开局底部确实存在“选择下一步行动”，作用是跳转到 `/sessions/{id}`，方向卡片在会话页才展示。这是用户反馈的中间步骤。
- 会话页的“上一页/下一页”用于已保存剧情的历史浏览，功能不同。此次取消中间步骤不等于删除历史回看能力。

### 目标体验

建议官方开局采用固定的 **开场插图 → 流式正文 → 方向卡片与自由输入** 顺序。

1. 确认角色和绑定入口后，提前解析、预取兼容的已发布开局图，在正文开始前确定图位；不等待实时生图。
2. 已确定展示图片时，图框尺寸固定，图片载入不得推移正文。素材缺失或读取超时则明确降级为无图开局；本次阅读不再突然向正文上方补插图片。
3. 开局与后续正文使用连续的阅读体验。正文完成并校验落盘后，在下方直接展示后继方向和自由输入，不要求用户再点击进入操作页。
4. 路由与存档绑定可在内部完成，但不得重复生成或播放开局、重置滚动位置，或丢失正在进行的请求。
5. 可见预设方向出现时立即启动预生成；上一段未校验完成时不能提交依赖它的下一段。

后续普通段落不默认配图。名场面仅在状态兼容且布局已确定时展示；用户主动请求的晚到图片放到稳定的独立位置，不插到已读文字上方。具体超时阈值留待加载测量确定。

## R4：方向数量与质量

`api_turn_drafts.visible_choices()` 对开局只取前两条，后续收集两条即返回；不足时补“观察周围”“梳理线索”。所以目前确实是固定两项，不是模型根据场景判断只有两种方向。

还发现上述六个分支的原始 `nextDirections` 都含“关键推进：拒绝”。当前开局对应摘要实际上描述“灯底石屑拒绝被冲走”，不能成为玩家可执行的“拒绝”行动。这说明问题也包括原始事件提炼与后继方向更新质量，单改数量不够。原始字段不完全等于最终可见菜单，不据此声称六页都显示同一按钮。

建议：

- 常态提供 2–4 个有实质区别的方向，特殊场景按真实可行性减少，不机械补齐；终局不再生成普通续写方向。该数量范围是设计建议，待成本与试玩验证。
- 每项明确“做什么、针对谁或什么、可预见的风险/取舍”，例如交涉、调查、求援、离开；没有足够依据就不强造某一类。
- 从当前地点、伤势、能力、物品、已知线索、角色目标和上一段实际结果推导；退出或死亡的人物不能继续成为当面交互对象。
- 不把尚未知晓的秘密写进选项，也不把所有选项都导向同一个结果。
- 自由输入持续可用。所有可见预设方向都遵循已确认的正文预生成要求；从两项扩展时同步测量未采用 token、并发与等待时间，不能展示四项却只为两项预生成。

## R5：自定义方向必须成为实际剧情后果

明确区分两类输入：

| 输入语义 | 应兑现的内容 |
| --- | --- |
| “我试着攻击他” | 实施攻击并根据世界状态结算；允许有明确原因的失败 |
| “下一段剧情让他死亡” | 下一段写出有因果的实施过程、死亡结果与即时影响，并保存死亡状态 |

当前 `performed/blocked` 审查能检查行动是否出现、是否实际尝试，不能单独保证第二种输入要求的结果成立。将“杀掉他”改写成“你握紧拳头”“被劝阻后作罢”或仅放进下一轮选项，不满足本次要求。不能因为原著后面需要此人，就保留其剧情免疫。

后续执行约束：

1. 提取行动主体、对象、明确结果、发生期限、永久性及玩家限制；“下一段”不能无限延期。
2. 根据已知能力、物品、环境及已有关系安排成立的剧情方法；不得靠突然升级、凭空神器或无依据的援手硬凑结果。
3. 明确结果与世界硬规则或既成历史确实冲突时，在正文生成前说明具体冲突与可行解释，不得暗中改成失败后仍报告已响应。一般困难应通过合理叙事解决，不能泛化为拒绝重大偏离的理由。
4. 用户已明确“死亡”时不再询问是不是死亡；仅“永久下线”等存在死亡/离队歧义且影响后果时，才处理必要歧义。
5. 正文证据与状态变化一起校验、提交：死亡/离队、物品去向、在场情况、关系、目标和后继事件同步更新。尚未被 NPC 得知的事件不能自动传播给所有角色。
6. 后续方向、图谱、素材匹配与收尾读取同一分支事实，不能下一段复活，也不能靠新增替身强行回到原著。

此项属于既定 P3 的核心工作，不因 P1 的普通行动响应测试通过就视为完成。验收必须包含明确结果在当段兑现，以及至少五回合后续和保存恢复中的持续有效性。

## R6：按角色维护目标，而非所有人共用一条主线

当前太虚角色统一显示“探索这段故事，走到属于你的结局”；雨夜故事才有专门的 `ROLE_GOALS`。`current_task` 又可能直接取第一条开局行动或路线方向，将可选行动混同为任务。

目标应分为角色原始动机、当前阶段目标、玩家主动确立的新目标。下面是依据官方开局信息提出的初始表达，不是本轮已写入故事包的数据：

| 角色 | 可作为目标的已知依据 | 需要避免 |
| --- | --- | --- |
| 陆照临 | 查明父亲陆沉舟失踪的真相；眼前需要处理山门关闭与灯的线索 | 把救人或跨过封山线当作玩家已选择的任务 |
| 顾长离 | 面对首次外门试炼，并查清试炼木牌金屑的疑点 | 借用陆照临的寻父目标，或提前让她知道他的秘密 |
| 叶观澜 | 推动核对旧记录日期的矛盾，应对未经许可入宗的对质 | 预先判定谁伪造名册，或泄露尚未发生的拘押与逃离 |

顾长离、叶观澜更长远的目标仍需按母本审校，不能把以上眼前动机当作完整人物弧线。

建议目标记录来源、所属角色、建立时点、进度、依赖对象与变更原因，允许进行中、完成、转化、主动放弃、失效等状态。玩家拒绝寻父后，应保留放弃原因并建立新目标；不能每段都强迫其继续寻父。

“轨道纠正”用于修复因果断裂、提示尚未解决的问题和组织后续冲突。角色目标是叙事参考，不是推翻玩家选择的权限。关键证人死亡后，只能根据已存在的线索转化调查方式，或承认某部分真相无法再追问，不能恢复证人来维持原路线。

## R7–R8：头像复用与人物状态

当前图谱仅画圆点、姓名首字及名字，点击仍会打开人物卡；`JournalPerson` 尚无头像与人物结局状态的展示字段。已有陆照临、顾长离、叶观澜肖像，可按稳定角色 ID 与 `portraitAsset` 映射复用。

后续展示规则：

- 主要人物：裁切已有角色图片作为头像，头像下显示玩家当前已知的名字；保留点击人物卡、关系线、拖动和缩放。
- 龙套与未单独绘制的人物：采用同一美术风格的简单头像库，以稳定角色 ID 选择轮廓、色彩或标识，避免刷新换脸；不额外调用生图。
- 已出场但尚不知姓名或身份的人物，继续使用“年轻弟子”等当前可知称呼，不能通过头像或名字提前暴露身份。
- 后端正式状态决定人物是否死亡或退出；展示层再按玩家知识范围投影，不从模糊正文自行推断，也不显示其他分支或未来事件。

| 当前分支中玩家已知的状态 | 图谱表现建议 | 含义 |
| --- | --- | --- |
| 活跃 | 正常头像与名字 | 不代表一定在当前场景 |
| 已确认死亡 | 灰度头像＋“已故” | 保留历史关系与详情，不再作为存活人物生成行动 |
| 永久离队/退出当前路线 | 灰度头像＋“已离队”或“已离场” | 与死亡明确区分，依照已确认的永久性限制后续事件 |
| 暂时离开 | 正常头像，可标“暂离” | 不等于永久下线 |
| 失踪/生死未知 | 正常或中性头像＋“下落不明” | 不能提前按死亡处理 |
| 受伤等状态 | 小型状态标识，详情展示依据 | 不单靠头像颜色表达全部身体状态 |

当前图谱的 `dim` 表示焦点之外的关系淡化，不能复用为死亡判断。灰度必须搭配文字，详情交互保持原有逻辑，内容随所回看的历史分支变化。

## 开发顺序与验收

本轮仅记录以下安排，未开始实施。

1. **开局体验修正（R2、R3）**：固定预制图与文字布局，合并开局阅读和行动入口。对应既有 P2 展示层收口。
2. **P3 结果与目标闭环（R5、R6、R8）**：先明确结果契约与目标更新，再联动关系图状态、后继事件与图片兼容。此项是叙事正确性的最高优先级。
3. **图谱素材复用（R7）**：复用已有画像、配置简易头像；可独立完成外观部分，但状态验收必须依赖步骤 2。
4. **方向与篇幅优化（R4、R1）**：在正确状态基础上改进菜单推理、动态数量、预生成预算与场景节奏，纳入 P4 长篇节奏验收。不能只提高输出上限。

| 场景 | 验收重点 |
| --- | --- |
| 三个角色分别开局，图片快/慢/失败 | 图文顺序稳定；没有晚到图片推移正文；不多点一次按钮就能选择方向 |
| 开局结束、方向出现、立即选择 | 每个可见预设方向启动预生成；未完成时接管已有任务；正文与状态不重复提交 |
| 简单询问、普通推进、重大冲突 | 篇幅匹配行动复杂度；有实际回应与变化，不靠重复描写凑字 |
| 两项和多项真实抉择 | 方向可执行、互有取舍、不剧透、不机械补项；预生成成本可追踪 |
| 要求下一段让关键人物死亡 | 当段出现符合世界状态的明确结果；死亡状态、图谱和后继行为一致 |
| 死亡之后继续五回合、保存恢复、回看旧分支 | 不复活、不误用含该人物的名场面；旧分支保持自身历史状态 |
| 换角色开局、主动放弃旧目标 | 目标符合本人知识与动机，玩家新目标被接受并影响后续安排 |
| 龙套、失踪者、未知姓名者 | 无额外生图调用；头像稳定；不把失踪当死亡，不通过图谱泄密 |

技术检查通过与叙事体验通过分开记录。完整验收仍需服务器＋桌面前端的真实模型试玩，以及未知原著读者对理解程度、行动兑现、阅读节奏和继续游玩意愿的反馈。
