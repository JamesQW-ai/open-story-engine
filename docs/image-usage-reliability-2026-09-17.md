## 问题与修复

图片统计总计原先接受负数、非有限数和非整数 token，展示分组采用不同的校验，可能出现总计与分组不一致。损坏文件被跳过、缺失调用数被当作零，也可能把不完整统计显示成完整成本。

`illustration_metrics.py` 现在共用同一套汇总规则：

- 调用数和 `total_tokens` 只接受非负整数，不接受布尔值、字符串、浮点数、`NaN` 或无穷大。
- `reported_tokens` 只累计调用数有效且大于零的有效回执；`usage_reported_calls` 是有有效回执的调用数。当前记录结构只保存一次响应，一份回执不能代表多次调用。
- `unmeasured_calls` 记录已知调用中缺少有效回执的数量；`unmeasured_attempts` 记录调用数缺失、非法，或零调用与用量回执矛盾的任务。两者任一非零，`total_tokens` 为 `null`。
- 明确零调用且没有用量回执的排队取消任务仍为已知零；一次调用返回合法零 token 也为已知零。
- 不可读取、非对象 JSON 等任务记录保留为未知尝试，同时计入 `unreadable_records`。无效访问／展示记录分别计入 `invalid_visit_records`、`invalid_display_records`，不混入有效命中率与展示耗时样本。
- 展示分组只接受布尔值 `true` 作为已确认。总计与两组的尝试数、调用数、有效回执数、已报告 token 及两类未知数逐项相加一致。CLI 输出为严格 JSON。
- 展示耗时在保留 `display_ms_samples` 原始样本的同时提供 `display_ms_summary`：有效样本数、平均值、P50 和 P95。百分位采用 nearest-rank，只引用实际回执，不对样本做插值。
- 访问回执保留 `published_hit`，并为私人图片记录首次访问时的 `private_cache_hit`。统计区分私人缓存命中、未命中和旧记录未知；旧回执缺少该字段时不当作未命中，命中率只使用已知样本计算。

`api_illustrations.py` 同时修复失败路径丢失回执的问题：供应商返回用量后，图片解码、下载或格式检查仍可能失败；现在失败时保存当前请求已知用量。新任务开始先清空前一个任务的回执，避免早期失败冒用旧用量。取消后的迟到失败只能补充回执，不能把任务改回可展示状态。

## 验收边界

统计只覆盖指定目录中仍保留的记录；空目录的零不证明历史总成本为零。调用数是本地记录的供应商请求尝试，不等于计费成功。用量回执不代表供应商最终账单，`billed_amount` 保持 `null`，取消不推断退款。

本轮未修改前端、提示词、正式存档或冻结小说，没有外部模型／图片调用。工程故障回归不代表真实正文质量或自然终局验收；NQ-001、END-001、SRC-001 继续暂缓，完整 P4 与大规模自动配图未启动。
