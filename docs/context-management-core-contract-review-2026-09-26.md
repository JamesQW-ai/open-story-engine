## 契约审查与实现

本轮逐项核对两组共 30 条输入、33 个冻结位置标签。标签允许选择表达主体、边界、位置及其肯否所需的最小连续片段；没有修改标签或给旧失败补允许范围。具体边界如下：

| 类型 | core 与完整范围的职责 |
| --- | --- |
| 独立的“没有人敢断定”前缀 | core 承载被讨论的位置；cue 引用独立前缀，程序派生的 qualified 保留整个命题 |
| 完整条件前提 | 仍由 premiseUnits 选择完整原文单元，不能并入结论 core，也不能遗漏连接词 |
| 与位置同片的推测、否定或词语提及 | 保留整个原片段，不删词；词语用法仍须语义判断 |
| 前置位置否定 | 必须保留，不按主体或边界实体起止自动裁剪 |
| 双主体与位置前置 | 分别选择对应主体的位置内容；不能假定位置必在人物称呼之后 |

[新提示](../test_support/prompts/context_qualifier_core_contract.md)替换原来“core 包含原有限定/否定”的混合定义，没有追加案例、历史、权威状态或额外正文。相较前轮，system 由 1,540 字符增加至 1,619 字符；user 消息逐字一致。提示 SHA-256 为 `87b2d9d7242c5bff6a19703c44542bf864f2659b592cbb1465c70f773282eed0`。这项澄清不是上下文压缩成果，也不是语义正确性的证明。

[审核展示模块](../test_support/context_qualifier_review_view.py)重新校验原始模型响应，只投影候选位置、逐字 core/qualified 引文及完整限定前提。它不使用模型 reason 生成事实说明，也不读取测试标签；引用或结构校验失败时不展示部分候选。模型原始 reason 仍完整保留在证据中，不改写、不隐去。

展示始终为 semanticStatus=unverified、reviewRequired=true、productionEnablement=false。“原文引用可定位”与“提取忠实且完整”是不同结论：空输出可以结构有效，错误限定也可能有真实引文，展示不能认证二者。这一模块只接入本次实验报告的 reviewView，未接入玩家界面或生产提交。

自由文字理由仍不可靠：denial:operator 的 reason 写“原文说沈砚秋在议事殿内，表达其在边界内”，省略无法断定；gate:condition_paraphrase 及部分双重限定理由省略条件。reviewView 保留了“没有人敢断定……”及“只要守门弟子点头……”的完整引文与限定，避免把这些理由直接显示为事实。但它同样如实保留 hall:word_mention 的错误候选限定，未替模型纠错或授予通过。

## 下一步清单与停止条件

当前阻塞已经包括**覆盖漏提**和**限定误报**。继续替换提示中的一句措辞，无法提供可靠的工程进展证据；下一步先审查提取任务边界，不追加同提示采样或把未见场景用作调参集。

1. 设计独立的覆盖契约：对可见原文中的待判断范围明确记录“已提出候选／明确非位置／未决”，不能用顶层空数组表示已经完整审查。程序只能检查覆盖记录是否完整，不能凭实体共现认定位置为真。
2. 先离线验证有界的候选范围索引：由已登记实体出现和原文单元定位可能需要判断的区域，不注入标签、历史结论或额外状态；明确无实体、代词、跨单元和多主体的未覆盖边界。未覆盖区域必须保留未决，不能静默丢弃或宣称完整召回。规模超预算则停止，不靠无限枚举增加上下文。
3. 把位置内容提取、词语用法与限定归属的判定职责分开，优先在一次请求的结构契约中验证；暂不增加第二个模型审核调用。必须覆盖“普通动作中附带位置”、纯动作无位置、词语提及、真实推测、否定和双主体，并同时统计漏提与误报，不能仅提高召回后忽略误报。
4. 候选设计及离线契约测试通过后再冻结预算实测。本轮 30 次已经结束；旧 29/30、当前 28/30 及早期失败全部保留，不从不同版本拼出一份全通过成绩。
5. 固定集和语义复审通过后才进入未见官方场景；来源支持、其他事实类型、完整正文与提交仍待分别验证，Jev 后置。
