# 自适应章节推进 v0.1

## 目的

玩家可以提出跨度很大的方向，但系统不能把它压缩成一次性结果，也不能用固定字数把每次生成裁成同样大小。本契约把“长期意图”和“当前可互动阶段”分开保存，使故事能逐步展开、自然断章，并允许玩家中途改道。

```text
玩家宽泛方向
  -> activeGoal（分支常驻）
  -> currentPhase（本回合只推进一段）
  -> 正文与高层方向
  -> 继续 / 改道 / 自然收束
```

## `storyArc`

每个生成 `BranchNode` 可保存一份 `storyArc`：

- `activeGoal`：当前分支的宏观目标。后续规划必须继承它，除非玩家的自由文本明确替换或完成该目标。
- `currentPhase`：本回合实际展开的当前阶段，而不是宏观目标的全部结局。
- `goalDisposition`：`started`、`continued`、`replaced` 或 `completed`，用于审计目标如何变化。
- `chapter.title` 与 `chapter.status`：当前章节的名称以及 `continuing`/`complete` 状态。未封章时要继承标题；封章需要阶段性冲突收束、实质场景/时间转换或可阅读的悬念钩子。

`storyArc` 属于叙事连续性，不是 `BranchState`。`RuleEngine` 与受控 `statePatch` 仍是人物位置、证据、场景路线与结局条件的唯一权威。

## 篇幅与节奏

规划器不再要求正文位于某个固定汉字区间。模型应根据当前阶段选择自然篇幅：普通阶段可以形成较完整的章节段落，紧张对峙或悬念处可以自然收短。唯一上限是防止异常响应占用存储和上下文的技术安全阈值，不是面向作者的篇幅规则。

当玩家说出“大跨度目标”时，方向评估器先从已公布方向中选出最早、最能合法承接的当前阶段。显式“先 X，再 Y”优先锚定 X；Y 仍作为完整 `playerDirection` 交给规划器保存，不要求玩家拆成一句单回合命令。规划器只写这一阶段，例如动机、阻力、准备、关系变化或伏笔；不得直接跳到多年后的最终成果。下一批高层方向应能推进、调整或中断这个目标。

编号选择可以继续复用未偏离的原著正文。自然语言输入即使锚定到存在原著正文的方向，也必须交给 Planner 生成一个 `diverged` 章节，从而保存 `storyArc` 并体现玩家的完整意图。两种路径都只能使用已公布方向的状态补丁和场景路线，不能借宏观目标绕过受控状态。

## 当前范围

CLI 会显示当前章节、主线目标和阶段，并在 `chapter.status=complete` 时显示“本章完”。本版本不实现多章摘要压缩、原著文件上传解析、章节目录选择或 Web 阅读器；这些功能需要独立的内容摄取、版权与长会话上下文设计。
