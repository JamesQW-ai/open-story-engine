## 交付结果

本轮补齐局部修复审计，修复同一请求失败重试覆盖旧审计的问题。未增加模型调用、审查轮次或扩写步骤；不修改冻结母本，不启动 NQ-001 真实质量攻坚。

原实现能保存部分原文和错误文字，但无法稳定区分修复请求失败、无效修复与修复后的复核失败；有效修复响应没有直接绑定到对应修复记录，复核发现的新问题也只剩文字摘要。同一请求重试时，旧失败任务被新任务替换，前一次审计会丢失。

现在每个 `local_repair_record` 保留原问题和前后正文，新增明确的阶段、错误码与问题类型；收到的修复响应不论最终通过与否均关联到该记录。同一草稿键重试时，将前次失败审计移入私有 `previous_attempts`，新审计单独记录，不递归复制历史。不同请求不混用历史；后续成功提交也不清空该私有失败历史。

## 记录契约

| 字段 | 含义与边界 |
| --- | --- |
| `beforeBody` | 本次修复前的完整候选正文 |
| `afterBody` | 替换成功后进入复核的候选正文；未成功应用修复时为 `null`，不把无效响应拼成假正文 |
| `issues` / `issueTypes` | 原问题及明确提供的类型；非结构化错误、不明类别为 `unknown`，不从错误描述猜类别 |
| `repairResponse` | 已收到的修复响应内容；未收到成功返回的响应时为 `null` |
| `outcome` | 请求中、等待复核、拒绝、复核失败或通过等既有状态 |
| `failureStage` | `repair_request`、`repair_validation`、`full_review`；无失败时为 `null` |
| `failureCode` | 模型／传输错误保留原错误码，本地校验为 `validation_error`；无失败时为 `null` |
| `failureReason` | 本次失败的完整原因 |
| `failureIssues` / `failureIssueTypes` | 当前失败时提供的问题清单与类型，与最初问题分开；复核新发现的状态错误不能覆盖原背景错误 |

模型响应被拒绝时，`repairResponse` 保存实际内容，`afterBody` 保持 `null`；只有成功应用过的修复才有后文。复核发生传输错误时，已经形成的 `afterBody` 保留，但结果标记为 `failed_full_review`，不能误判为模型没有返回修复。

审计字段仅进入本地记录，没有添加到模型提示中。原文、修复前后候选和私有失败历史不作为新事实、授权或正式状态。

## 验证

扩展 `tests_api/test_longform_repair_fallback.py`，新增 6 项，专项累计 9 项。每次运行自动枚举全部达标长篇；当前清单只有《太虚遗录》第一部，原始 102610 CJK、50 章。全部使用官方身份、长篇原文段落、临时数据库和故障模拟，不使用停用短篇。

验证包含：

- 非 JSON、空替换列表、占位标记修复均被拒绝，响应与失败阶段完整保存。
- 修复应用后仍触发视角校验错误，保存实际前后正文、原始响应与复核失败原因；下一次修复的前文等于前次修复后的正文。
- 行动、背景、连续性、状态四种明确类型均保留；故障注入只制造拒绝，不绕过验证生成成功结果。
- 原背景问题与复核新发现的状态问题分别记录，不覆盖、不凭错误文字推断。
- 修复请求传输失败与修复后复核传输失败可以区分；没有返回修复的情况不虚构 `afterBody`。
- 每种失败后正式 SQLite 的完整 dump 不变；关闭并重建服务后，私有失败审计逐项相同。
- 同一请求连续失败三次，每次重启后仍保留所有此前尝试；随后使用相同模型标识的模拟规划器成功提交，失败历史仍在。新请求的历史为空，不串档。

## 保留期限与未完成事项

这些记录沿用现有私有草稿库的生命周期：有效期参数为 600 秒，容量清理或删除存档也可能移除记录。重启回读验证在记录仍被保留的范围内进行，**不是永久审计档案**。旧版本已经丢失的记录无法补造，既有旧记录也未批量回填新字段。

本轮是审计字段补充，不改变可提交正文或权威状态的规则，因此不提升草稿校验规则版本。持久化读取兼容旧记录缺少 `previous_attempts` 的情况。

NQ-001 和 SRC-001 仍未解决。下一步可核查失败重试的耗时与 token 统计是否按实际调用归集，避免新一次尝试覆盖前次成本；仍不增加审查轮次，不将统计可靠性当作输出质量提升。
