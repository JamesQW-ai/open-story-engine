## 本轮范围

新增 `open_story_engine/dynamic_memory.py`，将已经由 `commit_consequences` 校验并进入分支状态的人物后果，转为下一回合可按需读取的短事实。覆盖死亡、离队、失踪、受伤和确认存活；不从普通摘要、自由文本断言或失败降级正文提炼确认事实。

确认权仍来自现有后果提交器：它检查玩家行动授权、正文哈希、事件核对、逐字证据和最终状态。记忆模块记录这些结果的绑定，不替代语义审查。哈希用于检测内容漂移，不是外部签名或新的授权来源。

## 写入与读取

1. 核心服务完成后果提交校验及本地正文守卫后，丢弃模型可能附带的 `contextMemory`，从本次真正改变的 `characterOutcomeStates` 建立候选，运行 `candidate → confirmed` 迁移校验。
2. 凭据绑定包 ID/版本/模块索引哈希、原始原因分支、父分支、原剧情节点、正文哈希、行动输入/选项/意图哈希、审核输入哈希和对应人物状态哈希。正文事实采用确定性短句，不复制原文段落或模型生成的原因描述。
3. `contextMemory` 保存在原因分支自身的 JSON 中，和正文、状态共用一个分支写入。API 在已有 `BEGIN IMMEDIATE` 事务内重建比对凭据，再写分支与请求回执；失败时一并回滚。没有新增数据库表或只读迁移。
4. 同一 request 的重试沿用已有分支与凭据；后续回合不重复持久化旧记忆。预生成规则版本从 `/19` 升到 `/20`，旧的待提交草稿不能跨版本直接提交。
5. 下一回合从存储返回的完整祖先链读取。只在包、原始正文、审核及当前人物状态仍匹配时允许使用；旧记录没有凭据时保持历史材料身份，不追溯性地补成确认记忆。
6. 用当前模块人物及本次玩家行动中明确提及的人物筛选。最多选择 4 条、合计 800 字符的事实正文，整条取舍，不截断、不把更多历史塞进提示。不是全量记忆回灌，也没有新增串行模型调用。
7. 在后代分支上只创建本回合的继承视图，保留 `parentMemoryId` 和原因来源，验证祖先链及未改变的事实。兄弟分支、其他会话、断开的 ancestry 无权继承。
8. 支持证据条目与来源追踪保留在完整 bundle 和事实/grounding 阶段，原始审核凭据仍在原因分支。写作与修复阶段通过 `dynamicMemory` 携带一次短事实，排除同源的重复 `allowedEvidence`；正文提示无承接文本时也不再重复注入动态记忆。

`memorySelection` 审计记录选中数量、事实字数和未选原因：`source_changed`、`state_changed`、`irrelevant`、`selection_budget`。失效采取不再装载的方式，不修改历史凭据，也不自动生成替代事实。数量/字数上限只是本模块的检索上限，总体上下文预算仍由原有预算器负责。

## 验证与边界

测试只使用 `longform_cases()` 确认的十万汉字官方长篇，数据库均为临时或内存数据库。功能测试中的审核输出为固定夹具，不是新的真实模型质量证据。

- 新增 `tests_api/test_dynamic_memory.py`，覆盖存储还原、正文/状态/输入/审核/包版本变化、伪造凭据、无关人物过滤、祖先继承、预算整条舍弃、事务回滚、旧记录/降级过滤，以及真实写作提示只注入一次。
- 在既有后果全链路测试中增加首次写入、相同 request 去重、五轮后重启再读取的断言。
- 在桌面游玩 API 测试中加入预生成产物凭据被篡改的情况，确认请求返回拒绝，正文、状态、审核记录和提交回执全部不落库。
- 未请求真实模型或生图服务，未修改正式会话、`.env`、官方小说或 StoryPackage。
