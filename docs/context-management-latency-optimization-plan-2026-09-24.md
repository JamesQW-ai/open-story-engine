状态：执行中；本文件记录在不降低审核、状态和正文可见性底线的前提下，继续压缩上下文与审核延迟的工作边界。

## 目标

当前真实候选选优回合的用户首字约 31.9 秒。Jev shadow 已在正文提交并回放后执行，因此 Jev 的约 5.4 秒调用不再阻塞首字。后续优化优先减少 DeepSeek 的输入冗余、错误重试和重复审核；Jev 只做不改变语义的传输优化和独立 A/B。

## 不可突破的底线

- 只有通过现有本地审核、权威分支提交和幂等校验的正文才能回放。
- `block` 模式仍在提交前等待 Jev；超时、结构错误、`rewrite`、`reject` 和 `allow_with_patch` 都不能写入分支。
- `shadow` 模式只能旁路记录，不能修改 `BranchState`、`statePatch`、StoryPackage 或正文。
- 上下文压缩不得删除当前行动契约、状态变化边界、当前 beat、必要公开证据、角色知识边界或来源哈希。
- 任何压缩后的质量、状态一致性和行动授权结果都必须与完整上下文做对照，不能只比较延迟。

## 上下文管理优化点

### P0：先量化再裁剪

每个阶段记录 `contextSha256`、字段字符数、估算 token、被省略字段和省略原因。至少分别记录 `result_contract`、`chapter`、`fact_extract`、`grounding_review` 和 `repair` 的输入体积，才能判断耗时来自正文生成、上下文长度还是网络重试。

### P0：删除重复注入

复用同一份 `ContextBundle`，避免在规划、正文、事实提取和复核阶段重复拼接相同的分支状态、行动契约和证据。`hardConstraints`、`resultContract`、`allowedEvidence` 和 `allowedMechanisms` 之间的重复字段要保留一份权威来源，再生成明确的阶段投影。

### P1：保留硬字段，压缩软字段

预算不足时按固定顺序删除文风样本、重复表述、较早连续性摘要和与当前人物／地点／动作无关的软证据。硬约束、玩家原始意图、状态边界、当前 beat、必要公开证据和来源 ID 不得截断。超预算时受控失败，不能通过模板填充或无限重试掩盖问题。

### P1：降低重试触发率

优先修复结果契约字段漂移、证据覆盖不足和行动要求丢失等确定性问题，让首次规划更容易通过。每减少一次完整重写，就同时减少正文生成、事实提取和多轮复核的远程调用。

### P1：阶段投影最小化

`chapter` 不携带未来 beat、其他分支和作者真相；`grounding_review` 只携带当前正文断言及其允许证据；`repair` 只携带原正文、结构化问题和原 bundle。阶段之间不得重新检索或自由摘要同一事实。

### P2：真实回放验收

使用官方长篇和固定动作，比较完整投影与压缩投影的首稿通过率、最终写入率、知识泄漏、行动越权、状态冲突、调用次数、输入 token、P50/P95 和用户首字。压缩版本必须在质量门槛不下降时才进入默认配置。

## Jev 延迟优化

已完成的安全优化：

- `shadow` 审计在正文回放后异步执行，不阻塞用户首字。
- 本次增加紧凑 JSON 序列化，只移除网络空白字符，不删除任何审核字段。
- Jev 仍无自动重试，网络失败只产生可审计失败结果。
- 本地前置校验失败时不发起网络调用。

固定 `jev-real-longform-review.json` 首个样本测得请求体从 6016 bytes 降至 5917 bytes，减少 99 bytes（1.65%）。这属于传输层微优化，不能单独解释端到端的秒级波动。3 秒 shadow 超时回放曾有 2 条 TLS 握手失败；将仅用于旁路审计的 `JEV_SHADOW_TIMEOUT_SECONDS` 临时调到 8 秒后，3 条可调用样本全部完成，结论准确率 100%，延迟 P50 为 661 ms、P95 为 727 ms。该调整不改变审核规则，也不改变 runtime `block` 的 30 秒严格超时；完整记录见 `shadow-replay-timeout8-2026-09-24.json`。

Provider routing A/B 已完成：`JEV_PROVIDER_SORT=latency` 的 3 条可调用样本结论准确率仍为 100%，但延迟升至 P50 4972 ms、P95 8125 ms，因此不启用该选项，正式配置继续保持空值。完整记录见 `shadow-replay-provider-latency-2026-09-24.json`。

下一步只允许做以下 A/B：

1. 比较完整审核投影与去重后的等价投影，验证每个硬风险结论一致。
2. 比较固定 Jev 版本和低延迟路由，至少覆盖 `allow`、`allow_with_patch`、`rewrite`、`reject` 四类。
3. 记录成功调用 P50/P95 和 TLS／HTTP 错误率；不能用缩短超时造成的失败来伪装延迟下降。

Jev 的独立回放如果出现握手超时，只能标为传输不稳定，不能降低审核门槛或把失败当作 `allow`。当前端到端首字优化的主目标仍是上下文装配和 DeepSeek 重试减少。

## 验收门槛

- 质量：四类 Jev 结论不发生不可解释漂移；硬冲突、行动越权、知识泄漏和未来事实泄漏零放宽。
- 状态：`BranchState`、`statePatch`、分支幂等和失败不写入行为保持不变。
- 体验：首字 P95 不因压缩回退；shadow 模式不把 Jev 延迟加入首字时间。
- 稳定性：记录至少 20 条真实或固定回放样本后，再决定是否启用新的上下文投影或 Jev 路由。
