## 后续执行清单与进入条件

1. **冻结审核语义评测集。** 以保存的坏稿为固定输入，补充普通动作、正常等待、有来源事实的正例，以及否定、主体替换、条件变更的反例。分开计格式错误、误报、漏报；不能只统计接口成功或整体拒绝。
2. **验证审核方案。** 比较候选审核模型或明确的逐命题来源核对契约；来源的主体、属性、肯否、条件和时间必须支持完整断言。`current` 标签、有效引文或同主题词都不能充当支持证明。先在固定稿上验证，再决定是否调整生产链路；不继续叠加特例正则。候选配置未知时如实标记，不凭空声称模型切换有效。
3. **复跑有界的 production pilot。** 仅在固定坏稿能被可靠识别、正例不过度误拒后执行；记录首稿、有限 repair、最终人工式语义复核、调用数和失败阶段。不能靠反复生成直到出现成功稿。
4. **20 条配对全链回放。** pilot 稳定后进入；冻结同一已验证计划和来源状态，分别统计独立全链稳定性与上下文投影差异。完整 bundle 仅作负向对照，禁止进入生产。
5. **临时数据库提交验收。** 完整质量链路通过后验证状态投影、分支继承、重复请求幂等、失败不提交、坏稿不进入短期或动态记忆。正式数据库继续保持隔离。
6. **延迟与默认路径评估。** 在同等质量门槛下核对 token、调用数、首字和总时延 P50/P95；再决定默认路径。不得以少审、提前流出未审核正文或削弱硬规范换速度。
7. **Jev 独立实验。** 以上质量与提交验收通过后才进入；不担任正文作者或状态权威。

每项继续采用“推进 → 审核 → 修复 → 复审 → 下一项”。确定性工程修复通过与模型质量验收通过分开记录；当前第 1、2 项是后续重点，第 3 项及以后保持门槛，不能自动宣称已获通过。
