本轮推进用户 P6 的第一步：从正式分支历史还原路线监测记录，为后续局部大纲和收束控制提供可核查输入。NQ-001 继续暂缓，没有修改正文生成、审查、修复提示或降低状态提交标准。

## 新增能力

只读接口：`GET /api/v1/sessions/{session_id}/route-monitor?branch_id={branch_id}`，默认只读模式也可调用。返回契约版本 `route-monitor/1`，不写数据库、不初始化／迁移数据库、不调用模型。正常玩家界面不展示这些诊断字段。

| 字段 | 含义 |
| --- | --- |
| `branch_id` / `root_branch_id` | 本次选定分支及其真实祖先根节点 |
| `turns` | 当前祖先链上的行动回合数，排除入口和纯 Arc 选择；不使用全会话最大序号 |
| `recent_turns` | 最近 12 回合的状态变化类别和重复信号，包含可定位的分支引用 |
| `unchanged_state_turns` | 连续已跟踪状态未变的回合数；缺少历史快照时断开连续计数 |
| `repeated_action_turns` | 去除空白后连续相同输入的次数 |
| `signals` | 连续至少 3 回合状态未变、连续至少 3 次相同输入、当前整段正文与祖先正文相同 |
| `coverage` / `unknown_state_branches` | 祖先快照是否齐全及缺失位置；不是完整语义覆盖率 |
| `closure` | 已记录的活跃目标、开放问题以及无法确认的目标／问题清单 |
| `status` | 与故事手记共用的实际路线状态；主动结束后仍保留未解决问题 |

状态比较覆盖地点、原著游标／剧情范围、道具、持续实体属性、新人物／地点、已登记知识、关系、人物后果、目标和剧情问题。回合计数、`freeTextProgress`、事务编号以及新增事件摘要不会单独算作剧情推进。集合顺序和状态证据来源字段变化不算推进，实体属性内部有意义的列表顺序仍保留。

整段正文重复检查只比较去除空白后的精确内容，要求至少 80 字符，不是相似语义识别。连续相同输入、场景静止和重复引用可能是玩家有意为之；`review_recommended` 仅提示复核，不认定生成质量失败、不改变剧情、不拒绝等待，也不自动结束。结束后保留历史信号，但不再提示继续推进。

## 结束与历史边界

- 只沿选定分支的祖先链计算；兄弟分支、尚未提交草稿和失败正文不参与计数。
- 记录按需从存档重建，重启后无需额外模型调用或新表，不维护第二套可漂移的状态账本。
- 旧存档缺少目标／问题账本时报告 `unknown`；缺少过去状态快照时标明缺失，不用其他分支填补。
- 账本格式损坏、路线循环／绑定不一致返回受控 `409 route_history_unavailable`；当前分支没有状态仍返回 `branch_state_unavailable`。
- 提前结束不自动解决目标或开放问题。即使清单为空，`ending_eligibility` 仍为 `unknown`，不能替代正文交代和自然终局审查。
- 这是一次随调用生成的诊断视图，尚未接入自动收束规划或持续后台监控。用户改变路线后旧路线的监测结果不会写入新历史。
