## 现场操作顺序

1. 打开已有记录，回看开局，再向后翻页；打开“故事手记”展示目标、人物和线索，随后关闭。旧正文直接显示，不重复等待逐字展开。
2. 从书架正常开局。本次验证选择的是陆照临，开局展示预设背景图和身份正文。
3. 先点“请守门弟子救人”，观察回应。本次得到“交文书、通传执事”的条件；这是实际回应，不代表每次一定立即救活伤者。
4. 根据刚出现的剧情输入自由行动。例如只有在对方提出验看文书后，再输入“我把引荐文书交给守门弟子，请他通传执事救人。我留在封山线外，不碰空灯，观察伤者呼吸，等他带人回来。”不要无视现场正文机械照抄。
5. 再选一个与最新正文相符的选项。本次第三次行动是请守门弟子转交文书并作证，正文正常回应，物品交付得以承接。
6. 新正文完成后刷新页面，确认回到所读页。配图独立异步处理；第四页已验证触发补图，离页可取消绘制，未完成时保留明确标注的水墨过渡图。

本次自由行动约 27 秒完成提交；预设选项命中了后台准备结果。逐字展示还需要额外时间。这只是本次测量，网络与供应商响应会变化，不承诺每次同样快。

## 电脑重启后的启动方法

若页面和服务都已正常运行，无需重复启动。若关闭终端或重启电脑，分别开两个终端，保留运行窗口。

终端一：启动存有演示记录的 API（不要换成空数据库）。

```bash
cd /Users/James/open-story-engine
STORY_API_PLAY=1 STORY_PLANNER=openai JEV_RUNTIME_REVIEW_MODE=off \
STORY_DATABASE_PATH=/Users/James/open-story-engine/docs/evidence/continuous-play-2026-09-28/attempt-01/sessions.sqlite \
.venv-api/bin/python -B -m uvicorn open_story_engine.api:create_app \
  --factory --host 127.0.0.1 --port 8001
```

终端二：启动桌面页面，明确连接上述 API。

```bash
cd /Users/James/open-story-engine/web
STORY_API_PORT=8001 npm run dev -- --host 127.0.0.1 --port 5187 --strictPort
```

打开书架即可。`npm run demo` 对应历史局部回放入口，不是本次真实游玩的启动方式。不要为了处理端口占用直接结束不明进程；若页面原本可用，继续使用已有服务即可。

演示前可检查：

```bash
curl -fsS http://127.0.0.1:5187/api/v1/health
```

应看到 `phase:"play"`、`generation_available:true`、`state_updates_available:true`。健康检查只能确认配置和服务可用；汇报前正常新开一局并提交一次行动，才能再确认当时的外部模型连通性。当前开发检查已真实完成，不以健康检查代替游玩。
