## 实际修改

开局与续写共用三项浏览器呈现指标：`first_text_ms`、`full_text_ms`、`directions_available_ms`。开局计时从启动开局流程开始，包含前置图片准备的等待；提交成功后绑定真实 `session_id` 和根分支。记录新增 `kind: opening | turn`，保留独立 `attempt_id` 与幂等 `request_id`。

开局从 `/sessions/new` 转入正式会话属于同一阅读过程，不再随会话参数变化结束计时；组件真正离开时才记录中断。失败重试另起计时，但沿用同一开局请求。完整正文和方向时间只在对应内容实际进入页面后记录，失败和未到达阶段保持 `null`。当前为 React 更新后的浏览器呈现近似值，不是物理绘制时间或纯模型生成耗时；诊断范围和 50 次本地保留上限沿用 [上一批记录](p2-reading-flow-2026-09-16.md)。

共享草稿原先只有 `selected` 布尔值。两个调用共同等待一个任务时，其中一个调用异常退出，其 `finally` 会将该值清零；若没有后台订阅，工作线程会把仍有另一个等待者的任务取消。新增进程内 `selected_waiters` 引用计数：只有最后一个等待调用结束才解除接管，且不把等待者数写入持久化草稿。释放订阅也移入受 `finally` 保护的范围，防止释放步骤异常遗留接管状态。

复现测试在修复前失败：第二个等待者收到 `ReadError`、共享任务被取消；修复后仅生成一次、保存一个分支，第二个等待者正常完成。另有测试验证两个等待者全部离开后任务确实取消，没有因引用计数泄漏而继续保留结果。

边界：测试通过流式回调抛出连接异常模拟一个业务调用提前退出。生产 SSE 的正常断线仍只停止投递，允许已提交任务在后台完成，供同一请求重试恢复；本轮没有改成浏览器一断线就强制取消。后台无订阅任务仍在下一次回调或模型调用边界检查取消，不承诺撤销已消耗的供应商费用。

## P3 核查结果与后续

以下已有实现本轮通过 API 自动回归，不把它们重复记为新功能：

- 当前四个可见方向仅预生成一层，选择提交不递归生成后代；未选草稿不写正式分支。
