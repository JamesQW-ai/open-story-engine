## 篇幅

- 开场和续写均取消固定字数下限、目标字数和补足字数流程。叙事模型按本回合事件数量、转场及冲突复杂度安排篇幅，简单回应简洁写，复杂事件写清因果。
- 单次正文保留 3500 个非空白字符的上限。超长时优先删除可省略段落，保护开头和结果；无法删节才重新生成。不会截断结尾或为了接近上限扩写。
- 事实、人称、地点、道具、重复和阶段结果检查继续生效。进度取决于事件完成，不取决于字数。

## 剧情插图

- 本页正文保存并在前端显示后，自动为当前页的画面段落提交生图任务；正文不等待图片。图片根据该段已发生的剧情绘制，不读取未来剧情，最多每页四张。
- 提供异步状态查询、失败后手动重试、同段请求去重，以及独立于小说数据库的磁盘缓存。重读同一分支沿用它自己已生成的图，新的分支或新正文生成新图。关闭生图配置后，已缓存图片仍可读取。
- 正文不再轮换原有静态场景图。书架封面和手记封面仍是原有美术资源。
- 当前文本服务的模型列表未提供生图模型，**尚未配置或验收真实生图服务**。当前页面不会显示伪装成新生成的旧图。已通过模拟供应商的接口、异步、缓存、失败重试和浏览器加载测试。
- 当前接入约定是 `POST /images/generations`，解析 `data[].b64_json` 或 HTTPS 图片 URL；图片保存在数据库同级的 `illustrations/`。接口约定参考 [官方 Images API 文档](https://developers.openai.com/api/reference/resources/images)。兼容服务仍须实际联调，不代表所有供应商都支持相同尺寸或参数。

在仓库 `.env` 中填写，随后重启 API；密钥仅供后端使用：

```dotenv
STORY_IMAGE_BASE_URL=你的兼容服务地址，包含 /v1
STORY_IMAGE_API_KEY=你的密钥
STORY_IMAGE_MODEL=实际可用的生图模型名
STORY_IMAGE_SIZE=1536x1024
```

接口：

- `POST /api/v1/sessions/{sid}/branches/{bid}/illustrations`：异步生成缺失图片；`?retry=true` 仅重试失败图片。
- `GET /api/v1/sessions/{sid}/branches/{bid}/illustrations`：只读查询 `available` 和每张图的 `index/status/url/alt`。
- `GET /api/v1/sessions/{sid}/branches/{bid}/illustrations/{index}/image`：读取缓存图片，先校验会话与分支绑定。

当前任务队列在内存中，进程重启后未完成任务可在下次访问时重建；已完成图片保存在磁盘。尚未实现跨图人物面貌的一致性约束。

## 人物关系图

- 人物节点仍只来自当前路线已出场人物。连线从当前已读正文中明确的关系或直接互动提取，显示朋友、协助、交谈、交锋或相遇等标签。
- 不直接展示源故事包中的人物关系，防止剧透；没有充分依据的两个人保持不连接。当前提取是保守的规则识别，尚不能识别所有跨段代词指代。
- 主角居中高亮；支持拖动人物、平移、缩放与复位，悬停突出相邻联系。点击或键盘 Enter/空格打开原身份卡，保留身份与一段动态总结。
- 回溯或切换分支重新读取该路线的节点及连线，不带入其他分支信息。
