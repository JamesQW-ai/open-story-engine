## 用途

集中维护模型任务模板，通过 `render_prompt(key, **fields)` 调用。小说资料、玩家输入、状态及上下文筛选仍由业务代码提供，校验器与状态提交规则仍由代码执行。

## 目录

| 目录 | 内容 |
| --- | --- |
| `reader/` | 玩家视角、正文、开局、行动核对、删节与修复 |
| `actions/` | 通用行动解释、独立授权、独立事实提取与核对 |
| `consequences/` | 永久后果与角色目标；业务模块按原顺序拼接通用行动规则 |
| `core/` | 共创核心正文、扩写、事实审查与修复 |
| `legacy_rainy/` | 既有雨夜专用模板，保持原调用条件，不作为所有小说的通用规则 |
| `legacy/` | 兼容方向判定模板，不开放旧产品入口 |

`manifest.json` 登记模板 ID、组成文件及允许字段。当前是 39 个主要模板；短条件指令、数据标签、结构化消息的 JSON 字段与数据装配仍在原功能文件中。作者侧已发布的绘图素材描述也保留在内容目录，没有复制进通用目录。

## 调用

```python
from open_story_engine.prompts import render_prompt

instruction = render_prompt('reader.perspective', name='顾长离')
```

模板用 `{{ name }}` 表示字段，JSON 示例中的普通花括号无需转义。调用必须提供所有且仅提供登记字段，值须显式转成字符串；JSON 使用调用方原有序列化方式。缺字段、多字段、未知模板或未格式化值会在调用模型之前失败。

替换只进行一次，字段内容不会再次作为模板解析。模板不会执行 Python 表达式、读取环境变量或替调用方查询故事数据。空白与换行按原样保留；部分模板没有末尾换行，这是迁移前的实际消息内容，不要为了排版自动添加。

各任务的 `system` / `user` 角色和数据范围继续由原调用点维护。尤其不要给独立事实提取器增加玩家输入、行动契约或预期最终状态；它只提取实际正文，之后由另一审查步骤进行比对。统一模板目录不意味着将全部规则和上下文发给每个任务。

## 版本与生效

`catalog_version()` 返回目录版本与内容 SHA-256，涵盖已登记模板内容及字段。模板 ID、字段或文本改变都会改变摘要；修改说明文档不改变摘要。该摘要用于正文审计 `promptVersion`、开局生成记录及 `RULES_VERSION`。

目录在进程第一次使用时加载并固定。修改后需重启服务；当前不支持热更新，以避免同一请求混用新旧规则。采用整个目录摘要保守地使旧预生成草稿失效，暂不细分每条生成路径的依赖。正式保存的历史分支不受影响。

## 修改与验证

1. 修改对应模板；如字段变化，同时调整 `manifest.json` 与调用点。
2. 跑核心与 API 回归，检查独立任务的数据范围和旧草稿失效。
3. `tests_py/fixtures/prompt_migration_v1.json` 是首次抽取前表达式的固定基线。正常迁移应保持一致；未来有意修改提示词时，应明确记录行为变化并增加对应语义样本，不悄悄重算摘要让测试通过。
4. 纯搬迁用完整消息一致性验证；修改语义后，再复验真实模型失败样本与连续游玩。相同提示词不代表模型每次返回相同正文。

完整迁移验证及证据见 `docs/prompt-catalog-2026-09-15.md`。
